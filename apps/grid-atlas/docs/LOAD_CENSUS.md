# 수용가 교차 조사 원장

`data/load-project-census.json`은 유틸리티 공급 요청, PUC·PSC 심사, 송전계획, 고객 공시를 연결한 조회 원장이다. 기존 `bootstrap.json`의 모든 수용가 행과 `public/data/load-pipeline.json`의 모든 개별 행을 원문 레코드로 보존한다. 국가·권역·기업 집계량을 가상의 개별 사업으로 나누지 않는다.

## 조회와 분모

사이트의 **권역별 프로젝트 → 수용가 → 통합 조사 원장**에서 사업·신청, 중복·증설 연결, 전체 원문 기록, 조사 현황을 조회한다. 기본 목록에는 신청·기술 검토·공급계약·공사·운영·종료·개발 발표·진행 미확인을 모두 포함한다. 용량·고객명이 비공개여도 개별 요청을 식별할 수 있으면 보존한다.

- `rawRecords`: 출처별 원래 행. 기관 간 같은 사업이 여러 번 등장할 수 있다. 송전 지원·복수 고객·과거 검토 행도 유지한다.
- `entities`: 근거로 식별한 사업·신청 단위. 완전한 물리적 부지 일대일 대응을 보장하지 않는다.
- `decisions`, `entityAliases`: 확정 중복, 중복 가능성, 증설, 송전 지원의 연결 근거. 원문 기록은 삭제하지 않는다.
- `capacityFacts`: 요청·계약 MW, IT MW, 부지 규모, 자체 발전, MVA를 구분한다. 상충하는 수치를 임의로 선택하지 않는다. 계통 용량 합계는 활성 신청·계약이 확인되고 중복·증설·상충 문제가 없는 단위에 한한다.
- `attempts`, `survey`: 실제 조회 시각·성공·실패·대기와 EIA 사업자 조사 명부. 명부 등록이나 동일 주 소재만으로 조회 완료·특정 ISO 소속을 추정하지 않는다. EIA 명부에는 소매 공급사·본토 외 사업자 등도 포함된다. 조회율은 프로젝트 확보율이 아니다.

‘현재 원장에 실린 오래된 필요일’은 운영·미진행·미통전의 증거가 아니다. 송전 공사의 승인·완공도 고객 프로젝트의 모든 절차를 확인한 것이 아니다. 원문 기준일, 공개일, 실제 취득일, 원장 조립일을 구분한다. 새로 취득한 원문에는 실제 SHA-256을 보존하고, 과거 입력 JSON의 해시를 원문 해시로 바꾸지 않는다.

## 중복 제거와 점수 반영

동일 원문 식별자는 자동 연결한다. 서로 다른 문서는 공식 요청번호·동일 부지/계약 등 명시적 근거를 검토한 `same_entity` 결정으로만 통합한다. 이름·유사 용량만으로 자동 통합하지 않는다. `possible_duplicate`는 양쪽을 보존하고 비교 용량에서 제외한다. 같은 캠퍼스의 확장과 같은 고객의 별도 부지는 구분한다.

통합 조사 원장의 모든 항목이 평균 점수 분모에 들어가는 것은 아니다. `data/load-census-promotions.json`에 개별 검토한 **현재 활성 신청·공급계약**을 기록하면 `scripts/promote-load-census.ts`가 기존 `reviewed-load-projects.json`에 연결한다. 기존 ID는 유지하고 신규 사업은 `CENSUS::<canonical entity ID>`를 사용한다. MW·진행단계가 미공개여도 활성 신청은 분모에 포함되며 점수는 미산출로 남는다. 검토되지 않은 발표를 100점으로 채우지 않는다.

중복 가능성이 있는 상대가 미승격 송전 참고 기록이면 확인된 실명 신청만 점수 원장에 연결할 수 있다. 두 후보가 동시에 활성 점수 분모에 들어가는 것은 차단한다. 확정 중복은 기존 레코드와 근거를 보존하면서 활성 분모에서 한 번 집계한다. 단계 추정 점수는 기존 공통 모형을 사용하며 다섯 요건의 직접 확인과 구분한다.

## 재생성

검토한 출처·사업·연결 결정은 `data/load-project-census-fragments/*.json`에 저장한다. 새 원문 바이너리와 조사 작업 파일은 저장소에 커밋하지 않는다.

```sh
npm run data:census
node scripts/promote-load-census.ts
npm run data:reviewed
python3 scripts/build-load-pipeline.py
npm run data:census
npm run data:census:check
node scripts/promote-load-census.ts --check
npm run data:reviewed:check
```

프로젝트 판정이 바뀌면 연결된 조각 파일과 승격 검토를 함께 갱신한다. 위 명령은 실제 운영 SQLite/D1을 덮어쓰지 않는다. Pages는 검토된 seed를 임시 DB에 적재해 배포한다. 기존 관측·평가 이력은 삭제하지 않으며, 새 조사가 과거의 공개 상태를 소급 증명하지 않는다.

출처의 정기 접근·변경 점검은 [LOAD_CENSUS_REFRESH.md](LOAD_CENSUS_REFRESH.md)를 참고한다. HTML 변경 탐지는 신규 프로젝트의 식별·중복 제거·점수 재평가 완료를 뜻하지 않는다.
