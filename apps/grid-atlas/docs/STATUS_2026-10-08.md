# 2026-10-08 구축·검증 기록

> GitHub 업로드 전 최초 로컬 구축 시점의 기록이다. 이후 코드 게시와 운영 현황은 저장소 루트 README 및 GitHub 변경 이력을 확인한다.

기존 대시보드를 참고 자료로 보존하고 `apps/grid-atlas`에 독립 앱을 구축했다. 이 문서는 완료된 로컬 작업과 아직 가동되지 않은 운영 기능을 구분한다. 시각 표기는 한국시간이다.

## 구현·검증 완료

- React 대시보드: 전국 개요, 프로젝트 원장, 관측 시계열, 데이터 커버리지, 평가 방법론. 검색·유형/권역 필터·상세·CSV·모바일 화면 제공.
- 발전·저장·수용가의 5개 독립 접속 요건. 요건별 `20 × (1 − 진행률)`, 확인된 미진행 100점, 모두 완료 0점. 미공개는 별도 집계하며 평균에서 제외한다. 뉴스 근거 추정에는 URL·적용일·확인시각·판단 이유를 저장한다.
- 프로젝트 수 기준 평균, 발전·저장 복합 신청의 전체 분모 중복 제거. 사업자 간 동일 물리 사업 연결은 아직 완료하지 않았다.
- 같은 SQL 스키마의 로컬 SQLite / Cloudflare D1 API. 근거와 관측은 추가 저장하며 상태 기준일과 당시 알려진 범위를 구분한다. 과거 관측이 없는 기간은 자료 없음이다.
- NYISO·LBNL 공식 원문 취득 → 전체 범위 파싱·검증 → 로컬 API 적재 → 관측 및 실행 기록 저장 성공. 원문·정규화 자료·수집 보고서의 SHA-256 보존.
- 주간 또는 월간 GitHub Actions 수집, 수동 배포, 초기 적재, 검사 워크플로 준비. 계정 정보와 명시적 활성화가 없으면 예약 수집은 실행하지 않는다.

## 다음 운영 작업

1. Cloudflare 계정과 새 D1을 연결하고 계정의 CPU·저장·요청 한도를 검증한다. 현재 초기 자료 처리 비용 때문에 무료 요금제로 전체 기능이 운영된다고 보장할 수 없다.
2. 검토한 새 코드와 워크플로를 GitHub에 반영하고 최초 배포·읽기 대조·빈 DB 초기 적재를 실행한다. 이 작업에서는 커밋·푸시·공개 배포를 하지 않았다.
3. 실제 성공을 확인한 뒤 주간/월간 갱신을 활성화한다. 현재 자동 일정은 가동되지 않는다.
4. 다른 수용가 원장 확보·어댑터 추가, 물리 사업 식별, 용량 공백 해소를 진행한다. 비공개 원장은 별도 접근 경로가 필요하며 공개 자료만으로 전수 확보를 약속할 수 없다.
5. 공식 문서·뉴스를 실제 요건별로 검토해 평가를 축적한다. 뉴스 자동 수집·자동 판단은 아직 구현하지 않았다.
6. 과거 원문과 당시 원장을 날짜별로 적재한 뒤 과거 점수를 계산한다. 현재 자료를 과거에 그대로 복제하지 않는다.
