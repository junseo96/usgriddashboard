# 수용가 API 원문 대조 기록

## 월 표시와 보고서 판본

`snapshot_month: 2022-10-01`은 API의 월 정렬 기준이다. 원문을 직접 확인한 10월 사례의 실제 차트 기준일은 10월 20일이고 발표일은 10월 24일이다. `2022-10-01`을 실제 신청일·관측일 또는 월말 수치라고 표시하지 않는다. 새 계열의 `datePrecision=month`, `sourceAsOf=2022-10`, `publishedAt=2022-10-24`는 제공자 월 분류와 발표일을 분리한다. 정확한 원문 기준일은 위 표에 기록했다.

같은 “2022년 10월”에도 서로 다른 값이 존재한다.

- 2022년 10월 보고서 p.2: 10월 **20일** 37,323 MW.
- 2023년 1월 보고서 p.5: 10월 **28일** 37,073 MW.
- 2023년 2월 보고서 p.2: Oct-22 29,563 + 7,035 = **36,598 MW**.

이는 기준일 차이·후속 보고서의 변경 가능성이 있는 값들이다. 같은 날의 동일 정의라고 확인하지 않고 추출 오류로 단정하거나 합치지 않는다. 2023년 1월 보고서 p.4는 Jira 기반 추적 체계로 이전하며 Deferred 분류를 없애고 일부 MW를 Planned로 재분류했다고 설명한다. 시계열에서는 이와 같은 보고서별 정의 변경 가능성을 보존한다.

`kardashev-ercot-large-load-total` 계열은 각 보고서의 **직접 `total_mw`**만 표시한다. 같은 월에 여러 API 수정판을 수집하면 보고일, 제공자 추출시각, 첫 취득시각 순으로 최신 판본을 선택하며 과거 레코드는 보존한다. 응답의 `trailing_12mo`는 원자료에 남기지만 이 계열에 섞지 않는다. 보고서 판본이 바뀌거나 중간 월이 없으면 차트 선을 끊고, 전월 증감을 자동 산출하지 않는다.

## 기존 최신 자료와의 대조

2026-10-14에 확인한 API 최신 보고서는 **2026년 6월**이며, 10월 자료가 아니다. 총량 466,497 MW와 데이터센터 분류 420,812 MW는 기존 검토 자료와 일치한다. 새 API를 연결했다고 현재 기준일이 더 최신으로 바뀐 것은 아니다.

동일 최신 응답의 세부 분류는 전체 총량과 일치하지 않는 경우가 있었다.

| 세부 분류 합계 | 총량 466,497 MW와의 관계 |
| --- | --- |
| `by_status` 417,600 MW | 48,897 MW 부족. 기존 검토 자료에는 API에 빠진 단계가 있어 API만으로 완전한 단계 평균을 만들 수 없음 |
| `by_size_bucket` 488,884 MW | 총량보다 22,387 MW 큼. 개별 프로젝트 원장으로 전환하지 않음 |
| `by_zone` 199,962 MW | 전체 권역 분포로 사용하지 않음 |
| `by_type` 466,529 MW | 총량보다 32 MW 큼. 일부 MW는 제공자 코드가 비율×총량으로 계산한 값 |

분류별 기준·반올림·추출 방식이 다를 수 있으므로 차이 자체를 모두 오류라고 단정하지 않는다. 차이를 데이터 품질 경고로 남기고 해당 부분합에서 병목점수나 프로젝트 수를 만들어 내지 않는다.

API의 2026년 5월 직접 보고 값은 438,595 MW인 반면, 6월 보고서 속 `trailing_12mo`의 5월 값은 471,415 MW다. 6월 466,497 MW와 비교하면 각각 +27,902 MW와 −4,918 MW로 방향도 달라진다. 이 때문에 후속 재작성 값과 당시 발표 값을 하나의 자동 증감 계산에 섞지 않는다. 기존 공식 검토 계열과 새 API 계열은 이름·출처·비교 범위를 분리한다.

## 남은 검증 범위

이 작업에서 직접 원문 대조한 추가 월은 위 5개다. API가 반환한 모든 보고서의 모든 분류를 전수 검증한 것은 아니다. 제공자의 추출시각은 Grid Atlas의 원문 검증시각이 아니며, 첫 API 취득시각은 과거 시점에 자료를 알고 있었다는 증거가 아니다. 개별 고객 ID·신청·계약·통전 상태 원장은 이 집계 API에 없으므로 전국 시설 원장이나 개별 병목점수의 분모로 합산하지 않는다.
