# 수용가 API와 공개 구조화 자료의 정기 수집

신규 수용가의 프로젝트 자료와 운영 중인 전력수요(`load`)를 구분한다. 무료 공개 API·CSV를 기존 원장과 함께 사용하며, 집계 수치를 개별 프로젝트로 만들지 않는다. 현재 공개 사이트는 GitHub Actions에서 자료를 갱신하고 GitHub Pages로 게시하므로 별도 유료 API나 Cloudflare 계정 없이 아래 수집을 실행할 수 있다.

## 연결하는 자료

| 자료 | 범위와 역할 | 갱신 경로 |
| --- | --- | --- |
| Kardashev Labs ERCOT large-load API | ERCOT 전체 대형 부하의 공개 보고서 월별 집계. 고객 이름·개별 접속신청 원장이 아니다. | 매주 월요일 10:40 KST 목표, 새 발표본·정정 확인 |
| Epoch AI AI data centers | 미국 내 확인된 주요 AI 데이터센터의 시설·운영사·용량 추정·진행 근거. 전국 모든 데이터센터나 대형 공장 전수는 아니다. | 기존 시설 수집과 함께 매주 월요일 10:10 KST 목표 |
| Prince William County ArcGIS API | PJM 권역 버지니아 프린스윌리엄 카운티의 데이터센터 건물별 인허가. 캠퍼스·접속신청 건수와 다르며 MW는 미공개. | 기존 시설 수집의 `municipal` 그룹으로 주간 확인 |
| 기존 운영사·고객·산업 공개 목록 | 전국 시설·개발 원장. 개별 시설의 근거·용량·진행 모형을 유지한다. | 기존 주간 시설 수집 유지 |
| Watt Street Load Ledger | `/v1/loads` API 문서 확인. 무인증 실제 요청은 401. | 연결하지 않음. 인증·실제 응답·공개 게시 범위 확인 필요 |
| Yes Energy / interXdata | 여러 권역 대형 부하 프로젝트 제공을 안내하는 후보. | 연결하지 않음. 실제 샘플·접근권한·이용 조건 확인 필요 |

GitHub 예약 실행은 지연될 수 있다. 시설 수집과 API 수집은 같은 실행 잠금을 사용해 순서대로 main에 게시한다. 예약 설정, 실제 취득, 원자료 기준일, 데이터 커밋, Pages 배포는 별개의 상태다. 상용 API 인증정보를 채팅·소스·브라우저에 넣지 않는다. 일반 전력시장 수요 API나 발전 접속 큐를 수용가 접속신청으로 간주하지 않는다.

## ERCOT API 실행과 화면

```sh
npm run collect:load-api
node scripts/build-history.ts
npm run data:load-api:check
npm run data:history:check
```

저장소 Actions의 **Grid Atlas large-load API observations**에서 수동 실행할 수 있다. 기본 주간 일정은 `.github/workflows/grid-atlas-load-api.yml`에 있다. 실행은 별도 API 키를 요구하지 않는다.

**통합 시계열 → API 수집·이력**(`/#history/load-api`)에서 취득 성공 여부와 원자료 기준월, 발표본·정정, 합계 불일치, 원문 링크를 확인한다. **지표 시계열 → 신청·계약 용량 → ERCOT**에서는 Kardashev 계열을 기존 공식 검토 계열과 구분해 선택한다. 같은 기간의 여러 발표본을 합산하지 않는다.

호출하는 공개 주소:

- `https://data.kardashevlabs.org/ercot/large-load/history`
- `https://data.kardashevlabs.org/ercot/large-load/latest`
- 명세: `https://data.kardashevlabs.org/openapi.json`

`/ercot/large-load`는 404였으므로 사용하지 않는다. `/summary`의 전월 변화는 다른 보고서의 값을 연결할 수 있어 사용하지 않는다. `/observations`는 검토 당시 빈 배열이었으며, 명세의 이력 기능만으로 과거 발표본이 모두 확보됐다고 주장하지 않는다.

## 보존·검증

`data/load-api-observations.json`은 정규화된 공개 집계와 실제 취득 기록이다. 월(`snapshotMonth`), 보고일(`reportDate`), 제공자의 추출 시각(`providerExtractedAt`), 실제 취득 시각(`fetchedAt`)을 각각 유지한다. 원문 API 응답의 SHA-256과 정규화된 행의 SHA-256은 서로 다른 검증값이다. API 응답을 직접 내려받았다는 사실이 원 ERCOT 문서의 전체 대조 완료를 뜻하지 않는다. [원문 표본 대조](LOAD_API_VERIFICATION.md)를 참고한다.

같은 원문·월·보고일·내용을 다시 받아도 기존 취득 기록은 바꾸지 않는다. 새 보고서나 내용 정정은 별도 행으로 추가한다. 응답에서 사라진 행을 삭제하지 않는다. 네트워크 실패·빈 목록·필드 변경·비정상 값·최신 응답과 이력의 모순은 이전 정상 자료를 보존하고 실패 상태를 기록한다. 정상 총량과 서로 맞지 않는 세부 단계·규모·지역 합은 값과 경고를 함께 보존하며, 전체 분해표나 점수 분모로 승격하지 않는다.

최초 검토한 최신 API는 2026년 6월 기준 466,497 MW다. 10월에 API를 조회했다고 10월 신청량으로 바꾸지 않는다. 상태별 합계 누락과 기존 상세 단계표의 차이가 있어 기존 병목점수는 API 집계로 덮어쓰지 않는다. 계약·보증·통전 미공개를 0 MW나 미진행으로 바꾸지 않는다.

API 이력은 별도 제공자 계열로 자동 생성한다. 월별 직접 보고값을 선택하고 최신 보고서의 과거 재기재값(`trailing12mo`)을 이 계열에 끼워 넣지 않는다. 누락 월을 보간하지 않고 보고서 범위·정정 차이를 함께 보여 준다. 기존 검토 계열과 시설 점수 이력은 유지한다.

원 응답과 실행 보고서는 `.local/load-api/runs/`에 저장하며 공개 Git에는 커밋하지 않는다. GitHub 실행 artifact는 **90일** 보관한다. 커밋된 정규화 발표본 이력은 계속 유지되지만 원문 바이너리의 영구 보관을 뜻하지 않는다. 실패 실행도 이전 자료와 실패 표시를 검증한 후 게시할 수 있으며 Actions는 실패로 표시한다. 동시 main 변경으로 push가 거절되면 강제 push하지 않고 다시 실행한다.

## 전국 시설 자료와 중복

Epoch AI의 공개 CSV는 원문과 갱신시각·해시를 보존하고 기존 시설 수집의 staging 검증을 거친다. IT 전력, 시설 전체 전력, 신청·계약 용량을 구분한다. 과거 날짜가 적힌 추정과 미래 가동 목표를 확인된 착공·운영으로 바꾸지 않는다. 원문에서 상태가 불명확하면 기존 시설 모형의 보수적 가정임을 표시한다.

연구 자료의 운영 판정에는 공사기간·위성사진·목표일을 이용한 추정이 섞여 있다. 운영 완료 모형에 반영할 문장은 시설·시점·문장 내용의 검토 기록으로 제한한다. 새 운영 추정이나 근거 문장의 변경은 자동 수집 후 추가 검토 대상이며, 그 전에는 확인된 이전 상태 또는 보수적 상태를 유지한다. 자료 재취득·신규 시설 발굴·확인 가능한 공사 근거는 정기 실행으로 갱신된다.

PJM 지방정부 API는 건물별 허가 식별자와 상태를 사용한다. 건물 여러 동을 캠퍼스 여러 개로 부풀리지 않고, 확인할 수 있는 캠퍼스 관계는 별도로 연결한다. 건물 준공이나 허가 완료만으로 계통 통전·운영승인을 확정하지 않는다. 이 출처에는 전력용량이 없어 MW를 임의 배분하지 않으며 용량 가중 평균에도 추가하지 않는다. 상위 캠퍼스가 아직 연결되지 않은 건물 단계도 독립 프로젝트로 확정된 것이 아니므로 건수 보조 평균에서 제외한다. 개별 단계 점수와 목록은 계속 표시한다.

같은 캠퍼스·건물·단계임을 확인한 경우 기존 식별자와 연결하고, 캠퍼스와 일부 단계는 계층 관계로 관리한다. 이름 유사도만으로 병합하거나 새 출처의 모든 행을 순증 프로젝트로 세지 않는다. 용량 가중 점수는 기존 분모 규칙을 적용하며, 새로 확인한 과거 사건을 과거 앱 관측으로 소급 저장하지 않는다.

기존 시설과 연결된 연구자료의 부분 단계 사건은 `evidenceOnly` 참고 근거로 보존한다. 현재 상태뿐 아니라 과거 재평가에서도 기존 시설 전체의 진행단계를 덮어쓰지 않는다. 연구 자료의 부분 운영으로 캠퍼스 전체를 완료 처리하지 않는다.
