# 전국 대형 수용가 시설·개발 원장

2026-10-12부터 수용가 탐색의 기본은 개별 시설·캠퍼스·개발계획 원장이다. 공개 접속 큐에 나타나는 사업만 먼저 모으던 방식에서 범위를 넓혔다. 데이터센터 운영사 시설 목록, 기업 개발 발표, 정부·산업협회 제조업 투자 자료를 수집하고 사업별 위치·업종·진행 상태·용량 사실·출처를 보존한다. 이전 접속·계약 원장은 보조 탭에서 계속 확인한다.

## 데이터와 단위

`data/large-load-facility-fragments/`는 실제 수집한 운영사·하이퍼스케일·산업시설 입력이며 `data/large-load-facilities.json`은 검증·이력 보존·중복 판단을 거친 공개 원장이다. 수집 원문은 로컬 상태 디렉터리와 Actions 아티팩트에 보관하고 공개 저장소에는 넣지 않는다. 출처의 URL·SHA-256·취득시각·짧은 근거·알려진 원자료 날짜를 JSON에 남긴다.

- MW나 접속 신청 번호가 없어도 존재가 확인된 시설·개발계획을 등록한다.
- 시설·캠퍼스·확장 단계는 서로 다른 단위다. 명시적 동일 사업 판단은 한 ID로 합치고, 상위 캠퍼스에 포함되는 단계와 미해결 중복 후보는 합산·개발평균에서 제외한다.
- 기업의 서비스 도시나 클라우드 리전, 다부지 투자 발표는 물리 시설 하나로 바꾸지 않는다.
- IT 전력, 시설 전체 전력, 계통 요청·계약 전력, 현장 발전을 다른 측정값으로 저장한다. 이들을 더한 합계를 계통 신청량으로 표시하지 않는다. 생산능력 GWh/년·톤/년, 투자금액, 면적을 전력 MW로 환산하지 않는다.
- 주·도시로 유추한 권역은 지리상 추정이다. 실제 공급 전력회사나 ISO 접속 관할이 확인됐다는 뜻이 아니다. 경계가 불명확한 지역은 미확인으로 유지한다.
- 운영 중 시설도 원장에 남긴다. 현재 개발사업 평균은 계획·공사 시설을 대상으로 하며 운영·중단·취소를 제외한다. 상태 미확인의 보수적 가정 포함 여부는 별도로 선택한다.

전국 전수 목록이나 모든 시설의 실제 접속 신청량이 아니다. 표시하는 개수는 이 원장에서 식별한 단위의 수이며 서로 다른 사이트의 건물·캠퍼스·프로젝트 수와 직접적인 확보율로 비교하지 않는다. dcmap의 조사 방법을 참고했으며 해당 사이트의 개별 데이터베이스를 복제하지 않았다.

## 용량 가중평균

2026-10-13부터 대표 평균은 `Σ(개별 점수 × MW) ÷ Σ(MW)`다. 기존 건수 평균은 보조값 `countMean`과 `countAverageCount`로 유지하며, 개별 다섯 요건 점수 자체는 바꾸지 않는다. `mean`·`meanRange`는 용량 가중값, `averageMw`는 점수와 같은 범위의 양수 MW 분모, `averageCount`는 그 분모에 실제 기여한 기록 수다. 가중 가능 용량이 없으면 평균은 `null`이며 건수 평균으로 대신하지 않는다.

- 기본 가중 기준은 계통 요청 `requested_grid`다. 계통 계약·시설 발표 전력·IT 장비 전력은 별도 기준을 선택해 계산하며 서로 대체하거나 합치지 않는다.
- 시설에는 시설 범위, 캠퍼스에는 캠퍼스 범위 MW만 사용한다. 캠퍼스 일부 단계의 전력을 캠퍼스 전체 점수에 곱하지 않는다. 상위 시설의 하위 기록, 독립 시설 범위가 확정되지 않은 개별 단계, 미해결 중복은 제외한다.
- 같은 의미·범위의 동일한 MW를 여러 문서가 반복하면 한 가중치다. 상충하는 값은 최대값·합계를 택하지 않고 제외한다. MVA·현장 발전·의미 미확인 값은 가중치가 아니다. 공개 0 MW는 가중치가 없는 값으로, MW 미공개 `null`과 다른 제외 사유로 남긴다.
- 평균 옆의 GW·건수·용량 추가 제외 건수와 사유가 실제 범위다. 점수만 산출한 모든 시설에 MW가 공개됐거나 전국 용량을 모두 확보했다는 의미가 아니다. 상태 미확인 추정 포함 선택도 동일한 용량 조건을 만족해야 한다.
- 시설 CSV에는 선택 기준, MW 가중치, 가중평균 포함 여부·제외 사유, 선택 용량 사실·출처 ID, 현재 필터 평균의 MW 분모를 넣는다. 상세 화면에서 선택한 용량의 원문을 추적할 수 있다.

## 단계와 점수

다섯 절차에 각각 잔여 20점을 부여한다. 점수의 의미는 진행에 따라 남은 절차가 얼마나 큰지에 대한 모형이다. 직접 확인한 법적 승인 점수나 행정기관의 공식 점수가 아니다.

| 근거 | 기본 모형 | 표시 |
| --- | --- | --- |
| 발표·개발계획 | 15+15+20+20+20 = 90 | 초기 개발 가정, 낮은 신뢰도 |
| 부지·건물 공사 | 10+10+0+15+20 = 55 | 계통 보강과 구별한 공사 단계 모형 |
| 해당 시설 범위의 운영 | 0 | 운영 완료 모형, 개발평균 제외 |
| 현재 단계 미확인·관할 절차 연결 | 18×5 = 90 | 규정 참고 보수적 시나리오, 가능한 범위 0–100 |
| 현재 단계 미확인·규정 미연계 | 18×5 = 90 | 공통 절차 잠정 시나리오, 가능한 범위 0–100 |
| 중단·취소 | 미산출 | 기록 보존, 개발평균 제외 |

개별 신청·검토·계약·허가·통전 근거가 있으면 그 근거가 지지하는 요건만 보완한다. 실제 허가가 확인돼도 전력 계약이나 계통 보강이 끝났다고 추정하지 않는다. 공사 진행에 따른 인허가 점수도 모형의 가정이며, 모든 허가 문서를 확인했다는 뜻이 아니다. 동일 점수가 붙는 사업이 있어도 판단 근거와 미확인 항목은 각각 확인할 수 있다.

`data/large-load-jurisdictions.json`은 취득·확인한 공식 절차와 적용 범위를 담는다. 규정 존재·표준 처리기간·건물 착공만으로 개별 사업의 계통 절차 통과를 선언하지 않는다. 실제 전력회사·적용 대상이 미확인인 경우 그 규정을 적용한 점수 역시 조건부 시나리오다. 규정 미연계 점수를 관할 조사 완료로 표시하지 않는다.

## 이력과 자동 수집

실제 발표·착공·가동·중단 날짜가 확인된 사건만 생애주기 이력에 넣는다. 미래 준공 목표나 새로 페이지를 읽은 날을 사건일로 바꾸지 않는다. 과거 점수는 확보한 해당 사건에 현재 모형을 적용한 재평가이며, 당시 알려졌던 점수는 아니다. 자료를 알게 된 시각을 제한하는 조회도 따로 지원한다. 다만 시설의 동일성·중복 연결은 현재 검토 결과를 사용하므로, 과거에 별개 행으로 보였던 식별 분모까지 복원한 원장은 아니다.

시설 시계열에는 전국·권역별 용량 가중 집계와 개별 실제 사건을 함께 표시한다. 사건 재평가는 날짜가 확인된 사건·용량·계통 근거의 기준일을 사용한다. 해당 시점 이전의 날짜 있는 MW만 사용하며, 현재 MW나 날짜 미공개 MW로 과거 분모를 채우지 않는다. 별도 실제 수집 관측 보기는 보존된 관측일의 `knownAt`으로 이후 취득·정규화 내용을 차단한다. 두 보기 모두 날짜별 가중점수·GW·건수·범위·보조 건수 평균·추가 제외 건수를 CSV로 내려받을 수 있다. 차트는 확보한 날짜의 점만 표시하고 자료 공백을 선형 보간하지 않는다. `facilityCount`는 현재 검토된 식별 목록의 조회 범위이며 과거 실제 존재 시설 수가 아니다; 시계열의 산출 건수는 해당 시점 근거와 가중 용량이 있는 개발사업만 센다.

정기 수집기는 공식 목록을 재파싱해 신규 시설을 찾고 현재 속성 변화를 관측한다. 신규 발견일·상태 변경 관측일은 실제 사건일과 분리한다. 출처 실패나 목록에서 사라진 항목을 자동 취소로 처리하지 않고 직전 근거를 보존한다. 모든 출처의 기계적 상태 추출을 보장하지 않으며, 정성 보도 평가와 근거 충돌은 추가 검토가 필요하다.

기존 계약 원장의 연결 자료나 캠퍼스·건물 관계를 보강하는 파생 행은 `enrichmentOnlyFacilityIds`로 표시한다. 이런 행의 새 조립 시각은 해당 시설의 새로운 진행상태 관측이 아니다. 원본 시설 수집의 진행상태를 유지하면서 추가 계약·용량·식별 근거만 연결한다. 실제로 새로 식별한 기존 원장의 시설은 독립적인 원문 근거를 가진 일반 행으로 보존한다.

```sh
# 체크인 자료의 재조립·검증
npm run data:facilities
npm run data:facilities:check

# 실제 신규 목록 취득·정규화·변경 관측
npm run collect:facilities
```

예약 실행·실패 보존·게시 방식은 [FACILITY_COLLECTION.md](FACILITY_COLLECTION.md)를 참조한다. 출처 수집 성공, 원장 생성, GitHub 커밋, Pages 게시 결과는 별개로 보고한다.
