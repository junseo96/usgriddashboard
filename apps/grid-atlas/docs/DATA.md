# 데이터 출처와 갱신 범위

Grid Atlas는 별도 데이터 모델을 사용한다. 초기 자료는 사용자가 제공한 보관본의 공식 출처 레코드를 새 스키마로 정규화한 뒤, 2026-10-08 새로 취득·검증한 NYISO 및 LBNL 공식 원장 전체로 해당 두 범위를 갱신했다. 기존 앱의 점수 엔진·단계별 추정값·평가 이력은 가져오지 않았다. 보관본 파일 SHA-256은 `data/bootstrap.json`의 `provenance.referenceSha256`에 남고, 공식 원장 갱신의 실제 취득 시각·원자료 기준일·원자료/후보/보고서 SHA-256은 `provenance.sourceRefreshes`에 따로 남는다. 실제로 다시 취득하지 않은 출처에 새 확인일을 붙이지 않는다.

현재 자료에는 공식 원장, [검토한 개별 수용가 신청·계약](REVIEWED_LOAD_PROJECTS.md), 송전 지원·과거 기록과 [개별 정성 판단](PROJECT_STAGE_INFERENCES.md)이 있다. 전체 보존 행 수, 본토 48주/DC의 활성 적격 신청 수, 점수가 있는 평균 분모는 서로 다르다. 상태 재검토·중복 연결·자료 갱신으로 값이 바뀌므로 현재 수치를 문서에 고정하지 않는다.

| 확인할 내용 | 기준 데이터 |
| --- | --- |
| 전체 행·활성 적격 신청·유형별 수·알려진 MW | `bootstrap.json`의 `provenance.summary`와 최신 화면 요약 |
| 상태 보정·승격·평가 제외의 근거 | `project-status-reviews.json`과 `provenance.projectStatusImports` |
| 개별 물리 사업 연결·원문 수·수집 공백 | `load-project-census.json`의 `entities`, `rawRecords`, `decisions`, `survey` |
| 정성 판단·평균 포함·보류 사유 | `project-stage-inferences.json`의 최신 `judgements`, `audits` |
| 직접 요건 평가와 실제 관측 | 해당 API/DB의 평가 및 관측 기록 |

복합 발전·저장 신청은 유형별 수치에 겹쳐 나타나고 전체 분모에서는 한 번만 집계한다. 물리적으로 같은 사업의 사업자 간 재신청·중복 ID 연결은 아직 완료하지 않았다. 정성 판단 전체 행에는 이전 판단 이력도 있으므로 단순 배열 길이를 현재 점수 산출 수로 사용하지 않는다. 최신 판단 선택과 생성 검사의 요약 결과를 확인한다. 감사 결과의 판단 완료·검토 후 보류·미검토를 구분하며 `not_reviewed` 행은 검토 완료 수에 넣지 않는다.

용량 합계는 알려진 성분의 합이다. 미공개 성분을 0 MW로 대체하지 않으며 MVA를 MW로 변환하지 않는다. 각 레코드의 `capacityStatus`가 `partial`이면 일부 성분만 알려져 있다. 저장된 직접 근거 점수와 별도로 원문 단계 모형 `stage-proxy-v1`과 검토한 정성 판단 `qualitative-stage-v1`을 표시한다. 다섯 요건별 진행률은 모형의 가정이며 직접 확인 사실과 다르다. 개별 단계 근거가 부족하면 미산출로 남기고, 과거 단계 점수가 있어도 현재 활성 여부가 미확인이면 평균에서 제외한다. [배점·분모·한계](SCORE_COVERAGE.md)와 [정성 판단·이력 보존](PROJECT_STAGE_INFERENCES.md)을 참조한다. 과거 원자료 기준일을 새 관측일이나 평가 시점으로 바꾸지 않는다.

## 용량 가중 평균

2026-10-13부터 현재·과거 집계 평균은 점수와 해당 시점의 공개 MW가 함께 있는 범위로 계산한다. 점수 분자와 MW 분모의 대상은 일치해야 한다. 개별 배점과 관측은 보존하며, 용량 미공개 사업도 목록에 남긴다. 유형별 MW와 전체 공개 성분 합의 차이, 시설 용량 의미의 구분, 과거 누락 처리는 [집계 기준](CAPACITY_WEIGHTING.md)을 따른다.

## 전국 시설·개발 원장

2026-10-12부터 수용가 기본 탐색은 `large-load-facilities.json`의 전국 데이터센터·대형 산업시설 원장을 사용한다. 개별 접속 신청 확인이 시설 등재의 전제조건은 아니다. 회사 공식 시설 목록·개발 발표·정부·산업협회 공개 자료를 실제 취득하고 운영·계획·공사·중단·미확인 상태를 보존한다. `large-load-facility-fragments` 입력, 별도 중복 판단, 관할 절차, 원문 해시와 취득시각을 검증해 조립한다.

새 원장의 점수는 시설 진행 모형과 사용자 요청에 따른 보수적 가정을 포함한다. 규정 참고 가정과 규정 미연계 공통 절차 가정을 구분하며, 사실 미확인을 확인된 미진행 100점으로 처리하지 않는다. 이 예외는 이전 접속 원장의 직접 평가를 덮어쓰지 않는다. 시설·개발 원장의 평균과 기존 접속 원장의 평균은 다른 분모로 표시한다. [상세 기준](LARGE_LOAD_FACILITIES.md)과 [주간 수집](FACILITY_COLLECTION.md)을 참조한다.

## 출처와 공백

`data/source-registry.json`은 병합된 초기 원장의 출처 목록과 동기화한다. 현재 출처별 범위·갱신 상태는 이 목록과 화면의 출처·갱신 메뉴에서 확인한다. 수동 검토한 사례가 추가돼도 해당 출처의 자동 파서가 생기는 것은 아니다. 여기서 ‘원장 전체’는 해당 공개 문서의 전체 범위를 뜻하며 미국 전체 고객 신청을 뜻하지 않는다.

- 발전·저장: LBNL의 2025년 말 활성 신청 보관 자료. 소규모·배전 연결 및 모든 사업자의 완전한 포괄은 보장하지 않는다. 수집기는 공식 웹 색인에서 최신 연간 XLSX를 찾고 코드북·요약 탭·30개 열·신청 상태를 검증한 뒤 활성 신청 전체를 적재한다. 매주 검사해도 원자료 기준일은 실제 연간 기준일을 유지하며, 그 사이의 신청 변화를 추정하지 않는다.
- 수용가: NYISO `Load Projects`와 유틸리티·주 규제기관·고객 자료에서 식별한 개별 기록을 포함한다. `reviewed-load-projects.json`은 출처·신청/계약의 식별을 보존하고 상태 보정은 별도 검토 이력으로 적용한다. PUC 사건 번호나 전력회사 서비스 요청 ID도 허용하며 ISO 큐 번호를 요구하지 않는다. 정성 자료에서 추론한 개별 연결은 그 근거와 추론 표시를 남긴다. 철회·운영·묶음 사건은 활성 분모에서 제외하고, 용량과 상세 단계가 미공개이면 null로 보존한다. 배전·소매·계량기 뒤 고객 전체의 확보는 보장하지 않는다.
- 다른 권역: 송전 지원 필요, 과거 DPA, 전망 선별표, 회사 총량과 부지 허가만 확인한 사업은 참고 자료다. 확인된 단일 고객의 서비스 신청·계약은 별도 검토 후 포함하지만 집계·다부지 계약·기사의 사업 수를 그대로 개별 신청 수로 바꾸지 않는다. ERCOT 개별 원장 등 공개되지 않는 자료는 별도 공백이다.
- 뉴스·정성 자료: 검토한 공식 문서·고객 공시·보도에서 개별 진행상황을 판단해 `project-stage-inferences.json`에 출처 URL·원문 SHA-256·취득시각·기준일·판단 이유·가정·신뢰도를 기록한다. 이것은 저장된 직접 요건 평가와 별도 자료다. 자동 뉴스 수집·평가를 현재 가동하지 않는다.

추가 탐색 화면의 [수용가 파이프라인](LOAD_PIPELINE.md)은 출처·사례 행과 별도 집계를 제공한다. 기존 적격 신청 분모와 별개이며 개별 원장·계약·발표·송전 지원·과거를 구분한다. `load-project-census.json`은 이 원문들을 개별 사업과 연결하되 연결하지 못한 행도 보존한다. [7개 ISO/RTO 부하](DEMAND.md)는 실제 MW 관측과 현지일 피크를 별도 수집하며, 프로젝트 신청 MW와 합산하지 않는다. 부하의 15분 목표 게시 일정은 프로젝트 원장의 주간·월간 자동 적재와 별개다.

[권역별 대표 지표](REGIONAL_LOAD.md)는 명시적으로 검토한 출처를 사용한다. 발전 원장과 부분 수용가 원장의 공개 MW는 확보 범위가 다르므로 같은 전국 전수 분모의 수급 비교로 표시하지 않는다. 요약의 `knownCapacityCounts`는 유형별로 공개된 MW 성분의 수를 세어, 전체 미공개와 실제 0 MW가 공개된 경우를 구분한다.

별도 [수용가 권역별 진행 점수](LOAD_BOTTLENECK.md)는 `load-bottleneck.json`의 공개 계열과 시점을 제공한다. PG&E·ERCOT·ISO-NE·DTE·AES Ohio·Duquesne·Evergy·BPA·Georgia Power의 검토한 단계 자료와 NYISO 과거 원장을 사용하며 개별 원장·검토 신청의 분모에 직접 합산하지 않는다. 단계별 프로젝트 수가 없으면 MW 가중 지표로 구분하고, 계약 총량이나 운영 포함 여부가 불명확한 자료는 활성 평균을 만들지 않는다. Georgia Power의 혼합 추적군 참고지수와 별도로 검토한 개별 활성 신청 평균도 구분한다. 여러 권역을 표시해도 전국 수용가 수집 공백이 해소된 것은 아니다.

검토한 [사업자·기관 수집범위](LOAD_COVERAGE.md)는 `data/load-coverage.json`에 별도로 둔다. EIA의 2025년 final 조사 Frame 전체와 공식 BA·RTO 연결 근거를 보존하며 본토 관련·본토 외·소재 미확인과 권역 연결 미확인을 구분한다. 현재 기관별 수는 데이터셋과 화면에서 확인한다. 이 명부는 프로젝트 수나 물리 송배전회사만의 분모가 아니다.

수집범위 자료에는 CEC·SCE·SDG&E, MISO 권역 조사와 MTEP, PJM 전망구역·LAS 제출기관 등 더 넓은 근거를 연결한다. CEC의 데이터센터 요청·문의 취합과 PG&E의 단계 점수도 범위·기준일이 다르다. 전국 신고 명부와 공개 자료의 확보 범위가 넓어져도 모든 고객의 현재 신청·단계 이력을 확보한 것은 아니다. 회사별 미연결을 신청 없음이나 확인된 비공개로 바꾸지 않으며, 자료가 있는 회사의 점수를 권역 전체로 확대하지 않는다. 이 별도 출처 목록의 추가만으로 개별 원장 적재 상태나 DB의 적격 분모가 바뀌지 않는다.

## 실행과 보존

체크인된 자료의 현재 분모와 생성 결과는 다음 읽기 전용 검사로 확인한다. 이 명령들은 새 원문 수집이나 운영 DB 적재를 수행하지 않는다. 검토한 개별 출처 입력 → 상태 보정 → 초기 원장 → 조사 원장의 연결과, 최종 원장 스냅샷에 연결한 정성 판단 입력 → 통합 추정 자료를 각각 검증한다. 상세한 생성 순서·이력 보존은 [정성 판단 문서](PROJECT_STAGE_INFERENCES.md)를 참조한다.

```sh
npm run data:reviewed:check
npm run data:status:check
npm run data:census:check
npm run data:inferences:check
```

`generatedAt`은 해당 데이터 산출물의 생성·검토 시각이다. 문서의 발행일이나 모든 프로젝트의 현재 상태 확인일을 뜻하지 않는다. 서로 다른 시점의 집계 차이는 실제 진척뿐 아니라 수집·식별·평가 범위 변경에서도 발생한다.

```sh
# 선택 사항: 원래 보관본을 다시 정규화하는 개발·재현용 명령이다.
# 공개 저장소에는 레거시 보관본과 수집 원문 아카이브가 포함되지 않는다.
# 초기 실행은 이미 포함된 data/bootstrap.json을 사용하므로 이 명령이 필요 없다.
# 직접 재현하려면 보관본의 data/와 해당 실행의 raw/·runs/를 별도로 준비한다.
python3 scripts/build-bootstrap.py --reference-dir /path/to/archive/data --refresh-report .local/collection/runs/20261008T035917283776Z-8c72a2bf/report.json

# 실제 원자료 취득 및 검증만 실행한다. API는 수정하지 않는다.
python3 scripts/collect.py --cadence weekly

# 월간 검사도 같은 수집기를 사용한다.
python3 scripts/collect.py --cadence monthly

# 명시된 API로 인증된 적재를 수행한다. 토큰은 환경변수에만 둔다.
python3 scripts/collect.py --source-id nyiso-load-register --cadence weekly --api-url https://YOUR-WORKER.workers.dev
```

`build-bootstrap.py --refresh-report`는 실제 원본의 바이트 수와 SHA-256을 확인하고 독립적으로 다시 파싱한다. 재생성된 행들의 정규화 해시를 수집 보고서와 대조하고, 후보 JSON의 출처 ID·전체 범위·시각·기준일·모든 행까지 대조한 뒤에만 초기 자료에 합친다. 변조되거나 출처가 다른 원본·후보는 거부한다. 원자료가 없는 상태에서 보고서만으로 최신 자료를 만들지 않는다. 이 명령은 JSON 파일을 작성하며 운영 또는 로컬 DB를 수정하지 않는다.

API 쓰기에는 `GRID_ATLAS_ADMIN_TOKEN`이 필요하다. HTTP는 루프백 로컬 API만 허용한다. API 리다이렉트는 거부하며 토큰을 원자료 요청이나 로그에 전달하지 않는다. 호출은 `POST /api/import` → 성공한 적재가 있을 때 `POST /api/snapshots` → 실행 결과 `POST /api/runs` 순서다. 여러 출처의 합동 원자성은 보장하지 않는다. 한 출처의 적재가 실패하면 그 출처의 직전 정상 상태를 보존하고, 실패를 새 정상 수집으로 표시하지 않는다.

기본 상태 경로는 `.local/collection`이며 `--state-dir`로 지정할 수 있다. `raw/<sha256>.bin`은 원자료, `runs/<UTC실행ID>/`는 실행 보고서와 검증된 원문 행·적재 후보를 보관한다. `state.json`은 마지막으로 성공한 정규화 결과만 가리킨다. 동시 실행은 파일 잠금으로 차단한다. TLS 검증, 20초 타임아웃, 최대 두 번 시도, 32 MiB 다운로드 한도가 적용된다. 잘린 HTTP 응답, 오류 값, 중복 ID, 바뀐 21개 열이나 상태 범례, 비정상적 원장 축소는 적재를 중단한다. LBNL은 공식 색인과 실제 XLSX의 원자료·해시를 각각 보존하고, 적재 출처 해시는 XLSX 바이트를 기준으로 한다. 출처 원문에 남은 날짜 이상치를 임의 날짜로 복원하지 않는다.

NYISO 어댑터는 공개 시트의 전체 범위와 상태 범례를 검증한 뒤 취득본의 전체 행을 보존한다. 단일 원장 기준일이 확인되지 않으면 `sourceAsOf: null`이다. HTTP 수정일, XLSX 수정일, 마지막 행 수정일, 실제 수집일을 전체 원장 기준일로 대신하지 않는다. 각 실제 수집 시각은 `lastCheckedAt`/`retrievedAt`에 기록한다.

수집 결과가 모두 검증·정규화됐으면 종료 코드 0이다. 실패, 비공개, 원자료만 취득되어 검토가 필요한 경우에는 1이다. 기본 두 출처 NYISO와 LBNL의 전체 범위 정규화가 모두 성공하면 `success`다. 그 외 미구현 출처 어댑터는 원자료만 취득하여 `parser_review`로 기록한다. 한 출처만 성공하면 `partial`로 기록한다. `--cadence`는 실행의 주기를 기록하는 인자일 뿐 예약 실행을 켜지 않는다. 예약 실행 설정과 계정 연결은 `docs/OPERATIONS.md`를 참조한다.

전국 수집 공백 해소, 나머지 출처 어댑터, 물리적 사업 식별 연결과 실제 근거 평가는 남은 작업이다. 별도 [공식 과거 시계열](HISTORY.md)에 LBNL 2020–2025년 원장, NYISO 2023–2026년 보관본·취득본, ERCOT 2022년 이후 확보한 발표값과 PG&E·PPL 자료를 추가했다. 해당 출처·날짜 범위만 조회하며 자료가 없는 과거 날짜의 점수는 생성하지 않는다.
