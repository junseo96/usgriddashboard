# 데이터 출처와 갱신 범위

Grid Atlas는 별도 데이터 모델을 사용한다. 초기 자료는 사용자가 제공한 보관본의 공식 출처 레코드를 새 스키마로 정규화한 뒤, 2026-10-08 새로 취득·검증한 NYISO 및 LBNL 공식 원장 전체로 해당 두 범위를 갱신했다. 기존 앱의 점수 엔진·단계별 추정값·평가 이력은 가져오지 않았다. 보관본 파일 SHA-256은 `data/bootstrap.json`의 `provenance.referenceSha256`에 남고, 두 공식 원장 갱신의 실제 취득 시각·원자료 기준일·원자료/후보/보고서 SHA-256은 `provenance.sourceRefreshes`에 따로 남는다. 나머지 61개 출처의 날짜는 바꾸지 않았다.

현재 초기 자료에는 원장·역사·송전 지원·계약 사례를 합해 13,182개 레코드가 있다. 본토 48주와 DC의 활성 개별 신청으로 집계 가능한 레코드는 8,513개다. 유형별로 발전 6,134개, 저장 3,954개, 수용가 53개이며 복합 발전·저장 신청은 유형별 수치에 겹쳐 나타나고 전체 분모에서는 한 번만 집계한다. 물리적으로 같은 사업의 사업자 간 재신청·중복 ID 연결은 아직 완료하지 않았다.

| 지표 | 초기 자료 |
| --- | ---: |
| 알려진 발전 용량 | 1,303,580.177421 MW |
| 알려진 저장 용량 | 552,283.954728 MW |
| 알려진 수용가 용량 | 14,232.9 MW |
| 용량 미공개 또는 구성 일부 미공개인 활성 레코드 | 1,539개 |
| 저장된 5개 요건의 직접 근거 평가 | 0개 |

용량 합계는 알려진 성분의 합이다. 미공개 성분을 0 MW로 대체하지 않으며 MVA를 MW로 변환하지 않는다. 각 레코드의 `capacityStatus`가 `partial`이면 일부 성분만 알려져 있다. 저장된 직접 근거 점수와 별도로, 검토한 원문 진행 상태에는 `stage-proxy-v1` 단계 추정 점수를 적용한다. 다섯 요건별 모형 가정과 직접 확인 사실은 구별하며 원장 단계가 불명확하면 미산출이다. [배점·분모·한계](SCORE_COVERAGE.md)를 참조한다. 과거 원자료 기준일을 새 관측일이나 평가 시점으로 바꾸지 않는다.

## 출처와 공백

`data/source-registry.json`에는 기존 60개 수용가 조사 출처, LBNL 발전·저장 원장, 별도 LG&E·Black Hills Wyoming 공개 사례를 합한 63개 출처가 있다. 출처 범위는 원장 전체 5개, 선별 원장 8개, 집계 23개, 사례 11개, 미검토 13개, 접근 실패 2개, 비공개 1개다. 여기서 ‘원장 전체’는 해당 공개 문서의 전체 범위를 뜻하며 미국 전체 고객 신청을 뜻하지 않는다.

- 발전·저장: LBNL의 2025년 말 활성 신청 보관 자료. 소규모·배전 연결 및 모든 사업자의 완전한 포괄은 보장하지 않는다. 수집기는 공식 웹 색인에서 최신 연간 XLSX를 찾고 코드북·요약 탭·30개 열·신청 상태를 검증한 뒤 활성 신청 전체를 적재한다. 매주 검사해도 원자료 기준일은 실제 연간 기준일을 유지하며, 그 사이의 신청 변화를 추정하지 않는다.
- 수용가: 현재 분모에 들어가는 검증된 원장은 NYISO `Load Projects` 전체 74행 중 활성 53행이다. 철회 17행과 운영 4행도 보존하지만 분모에서는 제외한다. 배전·소매·계량기 뒤 고객까지 포함하는지 미확인이다.
- 다른 권역: 송전 지원 필요, 과거 DPA, 전망 선별표, 산업 고객 계약·기사 등은 참고 자료로 보존한다. 그 건수를 현재의 개별 수용가 접속 신청 수로 간주하지 않는다. ERCOT 개별 원장 등 공개되지 않는 자료는 별도 공백이다.
- 뉴스: 자동 뉴스 수집·평가를 현재 가동하지 않는다. 확인 가능한 기사·문서의 링크, 실제 적용일, 판단 이유를 사용자가 입력한 뒤 추정 평가로 저장한다.

추가 탐색 화면의 [수용가 파이프라인](LOAD_PIPELINE.md)은 980개 출처·사례 행과 52개 별도 집계를 제공한다. 기존 적격 신청 분모와 별개이며 개별 원장·계약·발표·송전 지원·과거를 구분한다. 이 중 실명 사례는 44건이다. [7개 ISO/RTO 부하](DEMAND.md)는 실제 MW 관측과 현지일 피크를 별도 수집하며, 프로젝트 신청 MW와 합산하지 않는다. 부하의 15분 목표 게시 일정은 프로젝트 원장의 주간·월간 자동 적재와 별개다.

[권역별 대표 지표](REGIONAL_LOAD.md)는 명시적으로 검토한 출처를 사용한다. 발전 1,303.58 GW는 본토 발전 원장 범위, 수용가 14.23 GW는 NYISO 공개 활성 원장 범위이므로 전국 수급 비교로 표시하지 않는다. 요약의 `knownCapacityCounts`는 유형별로 공개된 MW 성분의 수를 세어, 전체 미공개와 실제 0 MW가 공개된 경우를 구분한다.

별도 [수용가 권역별 진행 점수](LOAD_BOTTLENECK.md)는 `load-bottleneck.json`의 9개 권역·13개 계열·53개 시점을 제공한다. PG&E·ERCOT·ISO-NE·DTE·AES Ohio·Evergy·BPA·Georgia Power의 검토한 단계 자료와 NYISO 과거 원장을 사용하며 위 초기 원장의 8,513건 분모를 늘리지 않는다. 단계별 프로젝트 수가 없으면 MW 가중 지표로 구분하고, 계약 총량이나 운영 포함 여부가 불명확한 자료는 활성 평균을 만들지 않는다. Georgia Power 118건은 부분 통전을 포함한 추적군 참고지수다. 7개 ISO/RTO와 두 추가 권역을 표시해도 전국 수용가 수집 공백이 해소된 것은 아니다.

## 실행과 보존

```sh
# 선택 사항: 원래 보관본을 다시 정규화하는 개발·재현용 명령이다.
# 공개 저장소에는 레거시 보관본과 수집 원문 아카이브가 포함되지 않는다.
# 초기 실행은 이미 포함된 data/bootstrap.json을 사용하므로 이 명령이 필요 없다.
# 직접 재현하려면 보관본의 data/와 해당 실행의 raw/·runs/를 별도로 준비한다.
python3 scripts/build-bootstrap.py --reference-dir /path/to/archive/data --refresh-report .local/collection/runs/20261008T035917283776Z-8c72a2bf/report.json

# 실제 원자료 취득 및 검증만 실행한다. API는 수정하지 않는다.
python3 scripts/collect.py --cadence weekly

# 월간 검사도 같은 수집기를 사용한다.
python3 scripts/collect.py --cadence monthly

# 명시된 API로 인증된 적재를 수행한다. 토큰은 환경변수에만 둔다.
python3 scripts/collect.py --source-id nyiso-load-register --cadence weekly --api-url https://YOUR-WORKER.workers.dev
```

`build-bootstrap.py --refresh-report`는 실제 원본의 바이트 수와 SHA-256을 확인하고 독립적으로 다시 파싱한다. 재생성된 행들의 정규화 해시를 수집 보고서와 대조하고, 후보 JSON의 출처 ID·전체 범위·시각·기준일·모든 행까지 대조한 뒤에만 초기 자료에 합친다. 변조되거나 출처가 다른 원본·후보는 거부한다. 원자료가 없는 상태에서 보고서만으로 최신 자료를 만들지 않는다. 이 명령은 JSON 파일을 작성하며 운영 또는 로컬 DB를 수정하지 않는다.

API 쓰기에는 `GRID_ATLAS_ADMIN_TOKEN`이 필요하다. HTTP는 루프백 로컬 API만 허용한다. API 리다이렉트는 거부하며 토큰을 원자료 요청이나 로그에 전달하지 않는다. 호출은 `POST /api/import` → 성공한 적재가 있을 때 `POST /api/snapshots` → 실행 결과 `POST /api/runs` 순서다. 여러 출처의 합동 원자성은 보장하지 않는다. 한 출처의 적재가 실패하면 그 출처의 직전 정상 상태를 보존하고, 실패를 새 정상 수집으로 표시하지 않는다.

기본 상태 경로는 `.local/collection`이며 `--state-dir`로 지정할 수 있다. `raw/<sha256>.bin`은 원자료, `runs/<UTC실행ID>/`는 실행 보고서와 검증된 원문 행·적재 후보를 보관한다. `state.json`은 마지막으로 성공한 정규화 결과만 가리킨다. 동시 실행은 파일 잠금으로 차단한다. TLS 검증, 20초 타임아웃, 최대 두 번 시도, 32 MiB 다운로드 한도가 적용된다. 잘린 HTTP 응답, 오류 값, 중복 ID, 바뀐 21개 열이나 상태 범례, 비정상적 원장 축소는 적재를 중단한다. LBNL은 공식 색인과 실제 XLSX의 원자료·해시를 각각 보존하고, 적재 출처 해시는 XLSX 바이트를 기준으로 한다. 출처 원문에 남은 날짜 이상치를 임의 날짜로 복원하지 않는다.

NYISO 어댑터는 공개 시트의 전체 범위와 상태 범례를 검증한 뒤 74행 전체를 보존한다. 단일 원장 기준일은 확인되지 않아 `sourceAsOf: null`이다. HTTP 수정일, XLSX 수정일, 마지막 행 수정일, 실제 수집일을 전체 원장 기준일로 대신하지 않는다. 각 실제 수집 시각은 `lastCheckedAt`/`retrievedAt`에 기록한다.

수집 결과가 모두 검증·정규화됐으면 종료 코드 0이다. 실패, 비공개, 원자료만 취득되어 검토가 필요한 경우에는 1이다. 기본 두 출처 NYISO와 LBNL의 전체 범위 정규화가 모두 성공하면 `success`다. 그 외 미구현 출처 어댑터는 원자료만 취득하여 `parser_review`로 기록한다. 한 출처만 성공하면 `partial`로 기록한다. `--cadence`는 실행의 주기를 기록하는 인자일 뿐 예약 실행을 켜지 않는다. 예약 실행 설정과 계정 연결은 `docs/OPERATIONS.md`를 참조한다.

## 2026-10-08 검증

독립 어댑터는 같은 날 12:02:29 KST에 TLS로 취득한 기존 NYISO 원본을 SHA-256으로 검증한 뒤 74행, 활성 53행, 14,232.9 MW를 재확인했다. 원본 SHA-256은 `8158c0eb16ef93ce0a4f9f0dd8316d5680edbefbaeaab3758d7eded2e53c8e9b`이다. 이 검사는 기존 취득물을 재검증한 것이며 신규 네트워크 수집이나 운영 적재를 의미하지 않는다. 새 환경의 최초 일반 네트워크 수집은 접근 오류를 기록했으며 정상 자료를 덮어쓰지 않았다. 이후 허용된 네트워크 취득에서 NYISO 원장을 새로 확인했고, LBNL 공식 XLSX도 12:52:11 KST에 취득했다. LBNL은 기준일 2025-12-31, 활성 8,513행·본토 대상 8,460행을 검증했다. 새 어댑터는 CAISO::1667의 원문 Solar 0 MW 성분을 유지하여 발전 유형 수가 보관본 대비 1개 증가하나 전체 신청 분모·알려진 MW 합계는 변하지 않는다. 12:59:18 KST NYISO와 12:59:19 KST LBNL 재취득에 이어 양쪽 적재·관측 저장·실행 기록이 성공했다. 체크인된 초기 JSON도 해당 실행의 원본을 다시 검증해 반영했다. 각 실행 결과는 보고서의 실제 시각을 기준으로 확인한다.

전국 수집 공백 해소, 나머지 출처 어댑터, 물리적 사업 식별 연결과 실제 근거 평가는 남은 작업이다. 별도 [공식 과거 시계열](HISTORY.md)에 LBNL 2020–2025년 원장, NYISO 2023–2026년 보관본·취득본, ERCOT 2022년 이후 확보한 발표값과 PG&E·PPL 자료를 추가했다. 해당 출처·날짜 범위만 조회하며 자료가 없는 과거 날짜의 점수는 생성하지 않는다.
