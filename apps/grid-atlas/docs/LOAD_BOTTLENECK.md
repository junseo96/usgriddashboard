# 수용가 권역별 진행 점수

**관측 시계열 → 수용가 권역 비교**에서 권역·출처·기간을 선택한다. 그래프나 기준 시점을 선택하면 단계별 분포, 배점 가정, 평가 분모, 미산출 범위와 원문을 확인할 수 있다. 선택한 계열은 CSV로 내보낼 수 있다.

2026-10-09 검토본은 **9개 권역, 13개 계열, 53개 시점**을 포함한다. 여기에는 미산출 시점과 같은 원장을 다르게 비교하는 계열도 있다. 7개 ISO/RTO 외에 West의 BPA, Southeast의 Georgia Power 일부 자료를 추가했지만, 미국 전체 수용가 원장이나 전국 평균을 확보했다는 의미는 아니다. 회사별 부분 범위를 서로 합산하거나 이 점수만으로 권역 순위를 매기지 않는다.

## 산식과 분모

`load-stage-v1`은 공개된 단계에 다섯 요건의 대표 진행률을 배정하는 분석 모형이다. 요건별 잔여점수는 `20 × (1 − 모형 진행률)`이고, 단계 점수는 다섯 값을 합한다. 인허가 취득률·실제 공정률·대기시간을 직접 측정한 값이 아니다. 출처의 정확한 상태 문구와 검토한 대응표만 사용하며 미공개 단계를 100점으로 채우지 않는다.

| 표시 방식 | 계산과 해석 |
| --- | --- |
| 프로젝트 동일 가중 | 평가 가능한 활성 신청의 점수 합 ÷ 평가 가능한 신청 수. MW를 프로젝트 수로 바꾸지 않음 |
| 용량 가중 | 평가 가능한 단계의 `MW × 단계 점수` 합 ÷ 해당 MW 합. 개별 프로젝트 평균과 합치지 않음 |
| 추적군 참고지수 | 운영·부분 통전이 포함될 수 있는 공개 집단의 별도 지수. 순수 활성 신청 평균으로 대체하지 않음 |

점수와 함께 전체 공개 범위, 평가 가능한 분모, 미산출 범위를 표시한다. 단계별 가중치가 없거나 분포의 합을 확인할 수 없으면 평균을 산출하지 않는다. 운영 포함 여부를 분리할 수 없는 경우 활성 평균은 미산출로 남긴다. 계약 총량만 있는 부분집합 역시 병목 평균을 만들지 않는다. 따라서 화면의 권역별 값은 전국 개요의 LBNL·NYISO 개별 원장 평균에 추가되지 않는다.

주요 대표 배점은 신청·검토 진입 전 100점, 신청·예비설계 혼합 90점, 계통영향 연구 대기 85점, 기술연구 80점, 연구승인 75점, 시설연구·설계 70점, 계약협의 55점, 계약·확약 기준 충족 50점, 접속 관련 공사 25점, 통전 허가 20점이다. 부분 통전은 추적군에서만 10점으로 대표하며 완전 운영 0점으로 바꾸지 않는다. 배점과 다섯 요건별 가정은 화면 및 `shared/load-bottleneck.ts`에 공개한다.

## 평균 곡선을 읽는 방법

신규 신청이 들어오면 기존 사업이 진척돼도 전체 평균이 오를 수 있다. 완료 사업의 이탈, 평가 가능 비율, 공개 기준의 변화도 평균을 바꾼다. 원하는 모양에 맞춰 과거 점수를 만들거나 곡선을 강제로 낮추지 않는다.

NYISO의 2023년 11월부터 2026년 10월까지 전체 활성 평균은 **75.5 → 75.4점**이지만, 다섯 원장에서 모두 활성·평가 가능했던 동일 7건은 **71.4 → 43.6점**이다. 전체 분모는 10건에서 53건으로 변했다. 고정 7건은 신규 유입 영향을 줄여 진척을 보여 주지만, 계속 남아 있는 사업만 고른 표본이므로 전체 처리 성과나 완료율을 뜻하지 않는다.

ERCOT의 관측 소비 제외 지수는 **2023년 4월 84.3 → 2024년 1월 80.1 → 2026년 5월 91.3 → 6월 88.2점**이다. 단계 정정·대상 연도 확대·LLIS 개편·취소 및 중복 정리가 있어 하나의 동일 모집단 곡선으로 해석할 수 없다. 정의나 자료가 단절된 시점은 선을 끊으며, 5월에서 6월의 하락도 순수한 사업 진척 개선으로 단정하지 않는다.

## 날짜·재생성·갱신

원자료 기준일, 공식 공개일, 보관본 포착일, 실제 취득시각을 분리한다. 원장 전체 기준일이 없으면 `sourceAsOf`는 null이고 공개일이나 실제 보관·관측 시점이라는 표시를 유지한다. 연·월·분기 자료의 그래프 정렬용 첫날은 실제 사건 발생일이 아니다. 타임스탬프는 원문 UTC로 보존하고 사용자 화면은 KST로 표시한다. 현재 모형으로 당시 원문 상태를 재평가한 결과이며, 당시 이 점수를 발표했거나 앱이 관측했다고 주장하지 않는다.

- `data/load-bottleneck-reviewed.json`: 수동 검토한 원문 단계·분모·출처·단절 사유.
- `data/history-nyiso.json`, `data/load-cohort-nyiso.json`: 과거 NYISO 전체 원장 집계와 동일 7건의 연결 근거.
- `data/load-bottleneck.json`: 위 검토 자료를 결합한 조회용 게시 데이터.

```sh
# 네트워크 수집·DB 쓰기 없이 검토 자료로 재생성
node scripts/build-load-bottleneck.ts
node scripts/build-load-bottleneck.ts --check
```

`--check`는 저장된 게시 자료와 재생성 결과를 대조하며 새 원문을 수집하지 않는다. 새 자료는 실제 원문·취득시각·SHA-256을 확인하고 단계 대응·분모·비교 가능성을 검토해 추가한다. 공백을 0점·100점·보간값으로 채우거나 직전 값을 현재로 이월하지 않는다.

`/api/load-bottleneck`과 `/api/load-bottleneck/export`는 이 자료를 조회하며 프로젝트 DB·직접 근거 평가를 변경하지 않는다. Pages 내보내기에도 포함된다. 실측 부하의 15분 목표 수집 일정과 별개이며, 이 기능이 프로젝트 원장의 주간·월간 자동 적재를 활성화하지는 않는다.
