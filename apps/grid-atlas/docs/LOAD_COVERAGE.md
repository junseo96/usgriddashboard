# 수용가 사업자·기관 수집범위

**관측 시계열 → 사업자·기관 수집범위**에서 권역별 통합 자료, 전력회사 전체 신고 명부, ISO/RTO의 공식 구역·역할 명부를 확인한다. 개별 회사의 자료가 없는 경우에도 조사 대상 명부에서 그 회사를 숨기지 않는다. 기존 단계 점수는 **수용가 권역 비교**에서 해당 회사·원장의 부분 범위로 유지한다.

처음 PG&E·DTE·AES Ohio를 우선 평가한 이유는 당시 확보한 자료에서 단계와 분모를 함께 검증할 수 있었기 때문이다. 그러나 점수를 계산할 수 있는 회사만 고르는 방식으로는 권역의 수집 공백을 설명할 수 없다. PG&E는 CAISO 전체, DTE는 MISO 전체, AES Ohio는 PJM 전체를 대표하지 않는다. 이번 자료는 공식 조사 명부와 권역 취합기관을 먼저 확인하고, 회사별 근거와 남은 공백을 연결하도록 범위를 넓힌다.

## 무엇을 확보했는가

| 자료 | 사용하는 목적 | 이 자료만으로 알 수 없는 것 |
| --- | --- | --- |
| EIA-861/861S 전체 신고기관 명부 | 전국 조사 대상과 공식 BA·ISO 연결 확인 | 현재 고객 신청 수·용량·단계 |
| ISO/RTO 구역·송전소유자·부하공급자·회원 명부 | 해당 공식 명부에서 누락된 조사 대상 확인 | 모든 소매 유틸리티·고객의 신청 전수 |
| 운영기관·주정부의 권역 취합 자료 | 회사 하나를 넘어선 요청·전망·송전계획 범위 확인 | 공개 집계 밖의 신청과 개별 사업의 진행 단계 |
| 회사·고객별 원장과 공시 | 신청·계약·기술검토 등 공개된 근거 연결 | 다른 회사 또는 공개되지 않은 고객의 상태 |

화면의 **기관별 근거 연결**은 검토 자료와 EIA ID를 직접 대조했다는 뜻이다. 한 건의 계약이나 전망 자료를 연결해도 이 상태가 될 수 있으며, 그 회사의 모든 프로젝트를 확보했다는 뜻이 아니다. 운영기관 취합 자료가 특정 회사를 간접적으로 포함하더라도 근거 없이 그 회사의 직접 연결 상태를 바꾸지 않는다. 연결 기관 수를 명부 기관 수로 나눠 프로젝트 수집률을 만들지 않는다.

**기관별 확인 대기**는 해당 기관의 개별 자료 연결을 완료하지 못한 상태다. 신청이 없다는 뜻도, 비공개가 확인됐다는 뜻도 아니다. 비공개라고 명시한 공식 문서가 있을 때만 그 사실을 출처와 함께 기록한다. 접근 실패·자료 미검토·원문에 수치 없음·기관이 명시한 비공개는 서로 다른 공백이다.

## 전국 EIA 명부

[EIA 공식 연간 자료 색인](https://www.eia.gov/electricity/data/eia861/)에서 확인한 최신 자료는 **2025년 final data, 2026-10-07 공개**다. [공식 ZIP](https://www.eia.gov/electricity/data/eia861/zip/f8612025.zip)의 Frame에 있는 **3,421개 고유 EIA 신고 ID를 모두 보존**한다. 이는 2025년 연간 신고기관 명부이며 2026년 현재 회원사 목록이나 3,421개의 고객 프로젝트를 뜻하지 않는다.

| 신고 주·소재 범위 | 기관 수 |
| --- | ---: |
| 본토 주만 확인 | 3,315 |
| 본토와 본토 외 혼합 | 22 |
| 본토 외만 확인 | 80 |
| 소재 범위 미확인 | 4 |
| 전체 신고기관 | 3,421 |

본토 관련 신고기관 **3,337개** 중 ISO/RTO만 연결된 기관은 2,295개, 비ISO BA만 연결된 기관은 923개, 양쪽에 연결된 기관은 67개, 권역 연결 미확인은 52개다. 회사 소재지만으로 본토 관련성이 확인되는 기관도 포함하므로 이를 물리 배전회사 수로 해석하지 않는다. 알래스카·하와이·미국령·캐나다에만 보고 주가 있는 기관과 소재 미확인 기관은 보존하고 별도로 필터링한다.

권역은 공식 BA 코드와 Utility_Data의 RTO 운영 신고로 연결한다. 예를 들어 CISO는 CAISO, ERCO는 ERCOT, ISNE는 ISO-NE, NYIS는 NYISO, SWPP는 SPP다. 주 이름이나 회사명만으로 권역을 추정하지 않는다. 비ISO BA는 실제 코드를 유지하고, NA·공란은 권역 연결의 근거로 쓰지 않는다. 한 기관이 여러 ISO/RTO와 비ISO BA에 함께 연결될 수 있으므로 권역별 기관 수를 더해 전국 기관 수를 만들지 않는다.

명부에는 투자자 소유 전력회사·공영·협동조합 외에 소매·도매 판매업자, 계량기 뒤 설비 공급자, 프로그램 운영자 등이 있다. EIA의 운영 신고, ISO의 회원 지위, 송전설비 소유, 배전 공급 역할은 같은 개념이 아니다. 특히 Texas 소매판매업자도 Bundled 매출을 보고하므로 묶음요금 판매만으로 물리 송배전 역할을 인정하지 않는다. 원문의 명시적 배전 활동, Delivery 자료 또는 배전설비 Service Territory를 따로 확인한다.

공식 명부의 ‘전체 항목’ 표시는 **해당 문서 명부를 끝까지 확보했다는 뜻**이다. 송전소유자 명부가 모든 소매판매자 명부가 되는 것은 아니다. 일부만 확보한 명부는 부분 확보로 표시한다. 비ISO 사업자와 권역 연결 미확인 신고기관도 전체 명부에서 조회할 수 있다.

CAISO 규모 비교의 대표 자료는 PG&E 단독 12.710 GW에서 **CEC의 23.278 GW 데이터센터 요청·문의 취합**으로 넓힌다. 원자료 기준은 **2025년 12월**, 공개일은 **2026-08-12**다. 신청 전 문의를 포함하므로 현재 정식 접속 대기량이라고 부르지 않는다. PG&E 공시와 중복될 수 있어 합산하지 않으며, California 주 전체와 CAISO BA의 경계도 구분한다. PG&E의 단계 점수는 기존 부분 범위로 유지한다.

PJM의 전망 연도별 표는 미래 부하 추정이지 과거 관측 시계열이 아니다. 0 MW 조정은 ‘신청 없음’이 아니며, 음수 조정은 피크 감소를 반영할 수 있다. Duquesne의 확인된 기술검토 사업 3건은 별도 선별 점수 계열로 추가하지만 PJM 전체 평균으로 확대하지 않는다.

## 검색·내보내기·출처

권역을 고른 뒤 기관명·공식 ID·자료 유형으로 검색할 수 있다. 전력회사 명부에서는 기관별 근거 연결 여부와 소재 범위도 필터링한다. CSV는 선택 조건에 맞는 **기관 명부(`utility`)와 검토 근거(`evidence`)를 별도 행 유형**으로 보존한다. 원문 출처, 기준일·공개일·실제 취득시각, SHA-256, 명부의 sheet/row 위치와 단위를 함께 제공한다. 서로 다른 범주의 MW·기관 수·프로젝트 수는 합산하지 않는다.

원자료 기준일이 없으면 null을 유지한다. 연간 EIA 기간, 월 단위 CEC 기준, 미래 전망 대상 연도, 공식 공개일, 실제 취득일을 구분한다. 화면의 실제 시각은 KST로 표시하며 원문 기준일과 공개 정밀도는 바꾸지 않는다. 자료 구성 시각이나 재배포 시각을 원자료 기준일로 사용하지 않는다.

구현은 `data/load-coverage.json`, `shared/load-coverage.ts`, `/api/load-coverage`와 `/api/load-coverage/export`를 사용한다. 조회용 Pages 내보내기도 같은 검토 자료를 포함한다. 명부·근거의 조회 기능은 프로젝트 DB와 점수 분모를 변경하지 않는다.

## 재현과 갱신

EIA 정규화는 원문 ZIP의 SHA-256을 확인한 다음 Frame ID를 기준으로 중복 제거한다. BA 표, RTO 운영 신고, Sales·Texas Delivery·Short Form·서비스 지역·계량·효율·수요반응 등 13개 workbook을 대조한다. 실제 신고기관이 아닌 Withheld/Adjustment 코드 88888·99999는 별도 원문 위치로 남기고 회사로 만들지 않는다. 공식 이름이 비슷해도 다른 EIA ID를 근거 없이 합치지 않는다.

원문 ZIP·XLSX·HTML과 로컬 수집 상태는 공개 저장소에 넣지 않는다. 검토한 정규화 자료와 원문 URL·취득시각·해시·위치를 남긴다. 재현용 파서의 입력은 별도로 확보한 ZIP과 취득 메타데이터이며, 자료를 다시 읽는 것만으로 새 네트워크 수집이나 운영 적재를 완료했다고 표시하지 않는다.

초기 실행·미리보기에는 체크인된 `data/load-coverage.json`을 사용한다. 아래 명령은 **외부에 보관한 원문·메타데이터·검토 입력이 있을 때의 재현용**이다. 해당 입력은 저장소에 포함하지 않으므로 체크아웃만으로 다시 수집하거나 조립할 수 있다는 뜻이 아니다. 앱 디렉터리에서 실행한다.

```sh
# 별도로 확보한 EIA 원문 ZIP과 실제 취득 메타데이터로 명부 정규화
python3 scripts/build-utility-universe.py \
  --zip /path/to/research/f8612025.zip \
  --source /path/to/research/zip-source.json \
  --index-source /path/to/research/index-source.json \
  --output /path/to/research/utility-universe.json

# 외부에 보관한 검토 명부·권역별 정규화 입력을 게시 자료와 대조
python3 scripts/build-load-coverage.py \
  --universe /path/to/research/utility-universe.json \
  --fragment /path/to/research/pjm-coverage-fragment.json \
  --fragment /path/to/research/caiso-coverage-fragment.json \
  --fragment /path/to/research/miso-coverage-fragment.json \
  --fragment /path/to/research/other-coverage-fragment.json \
  --check
```

명부 파서의 `--source`는 취득 메타데이터의 SHA-256과 실제 ZIP을 대조한다. `--source`·`--index-source`를 생략하면 알 수 없는 URL·취득시각·공개일을 null로 남기므로 게시 자료에 필요한 출처 검증을 대신할 수 없다. `--generated-at`으로 구성 시각을 고정하면 같은 입력의 정확한 재생성을 확인할 수 있다.

조립기의 `--links` 기본값은 검토한 회사-ID 교차표 `data/load-coverage-links.json`, `--stage-data` 기본값은 `data/load-bottleneck.json`, 출력 기본값은 `data/load-coverage.json`이다. 권역별 `--fragment`는 원문 자체가 아닌 검토한 정규화 입력이며 별도로 보관한다. `--check`는 게시 자료의 구성 시각을 유지해 입력과 대조하고 파일을 수정하지 않는다. 검토가 끝난 입력으로 재생성할 때만 `--check`를 제외한다. 두 스크립트는 네트워크 수집이나 DB 쓰기를 수행하지 않는다.

EIA 명부는 연간 공개 주기를 따른다. 권역 취합 자료와 회사별 공시의 갱신 주기는 별개이며, 주간·월간 점검을 하더라도 원자료가 바뀌지 않았다면 새 프로젝트 상태를 만들지 않는다. 이 화면의 추가는 실측 부하의 15분 목표 수집 일정이나 프로젝트 원장 정기 적재 설정을 변경하지 않는다. 신규 근거는 대상·단위·중복·현재/누적 범위·기준일을 검토한 뒤 추가하고, 단계와 분모가 확인되는 경우에만 별도 점수 계열로 연결한다.
