# 대시보드 화면과 조회 범위

[공개 대시보드](https://junseo96.github.io/usgriddashboard/)는 **전국 개요 → 권역별 프로젝트 → 병목점수 → 통합 시계열**의 네 메뉴로 구성된다. 요약에서 특정 권역·사업·점수의 근거와 과거 변화를 찾아가는 구조다. 메뉴 재구성은 기존 API·DB 평가 산식, 원자료, 적격 신청 분모를 변경하지 않는다.

| 확인할 내용 | 메뉴와 하위 화면 |
| --- | --- |
| 전국 현황과 권역별 부하·신청 규모 | 전국 개요 |
| 신청 ID·용량·진행 상태·개별 근거 | 권역별 프로젝트 → 개별 프로젝트 |
| 개별 원장 밖의 회사 공시·계약·요청 집계 | 권역별 프로젝트 → 수용가 파이프라인 |
| 실측 부하·일 피크의 관측 간격과 완전성 | 권역별 프로젝트 → 부하·피크 상세 |
| 유틸리티·기관의 전체 명부와 자료 연결 공백 | 권역별 프로젝트 → 사업자·기관 수집범위 |
| 수집 결과·원자료 기준일·마지막 확인 | 권역별 프로젝트 → 출처·갱신 상태 |
| 사업별 다섯 요건 점수와 평가 이유 | 병목점수 → 개별 프로젝트 평가 |
| 수용가 단계 분포와 회사·기관별 평균 | 병목점수 → 수용가 / 수용가 권역별 평가 |
| 점수 모형과 근거 적용 순서 | 병목점수 → 산정 기준 |
| 여러 공개 계열의 과거 값·분모·출처 비교 | 통합 시계열 → 지표 시계열 |
| 확인된 같은 사업의 과거 단계·잔여점수 | 통합 시계열 → 프로젝트 생애주기 |
| 앱이 실제 저장한 관측 시점 | 통합 시계열 → 앱 관측 기록 |

## 전국 개요

평균 병목점수, 평가·미산출 건수, 발전·저장 접속 신청 용량을 먼저 보여 준다. 평균은 **평가 가능한 공개 활성 신청의 동일 가중 평균**이다. 확보한 원장 내부 평가율을 미국 전체 프로젝트의 수집률로 해석하지 않는다. 현재 개별 수용가 평균은 NYISO 공개 원장 범위이며 수용가 전국 합계는 미확보로 표시한다.

**병목점수의 변화** 차트는 **발전·저장 장기**와 **전체 평균 관측**을 전환한다. 발전·저장 장기는 LBNL의 과거 연말 원장에 동일한 단계 모형을 적용한 별도 계열로, 상단의 발전·저장·수용가 혼합 평균과 대상이 다르다. 연도를 선택하면 평가 분모·미산출 건수·원문을 확인할 수 있다. 전체 평균 관측은 앱이 실제 저장한 관측 시점의 평균만 보여 준다. 확보한 관측이 하나면 점도 하나이며 이전 값이나 중간 시점의 점수를 만들지 않는다.

**권역별 부하와 접속 신청** 표는 7개 ISO/RTO의 최근 확보 부하, 일 피크, 발전·저장 신청, 검토한 수용가 요청·파이프라인을 나란히 표시한다. 최근 부하에는 관측 시각을 표시한다. 일 피크는 가장 최근 확보한 시장 현지일의 값을 우선 표시하며, 일부 구간만 확보했으면 **잠정**으로 표시한다. 이전에 하루 전체를 확보한 날의 피크가 따로 있으면 **범위·출처**에서 확인한다. 이전 관측을 현재 실시간값으로 바꾸지 않는다. 신청 명판용량·계약·문의·실제 소비는 범위가 달라 서로 합산하지 않는다. 각 행의 **범위·출처**를 펼쳐 기준일과 별도 참고값을 확인한다.

## 권역별 프로젝트

**개별 프로젝트**에서 발전원·저장전원·수용가와 권역을 선택한 뒤 사업명·신청 ID·원문 단계 또는 점수 상태로 검색한다. 행을 열면 진행 상태, 출처, 평가 근거와 제외 사유를 확인할 수 있다. 하이브리드 발전·저장 신청은 유형별 조회에 겹칠 수 있지만 전체 평균에서는 같은 원장 ID를 한 번 센다.

**수용가 파이프라인**은 개별 원장에 넣을 수 없는 회사별 요청·계약·발표·송전 지원 자료를 별도로 조회하는 화면이다. **사업자·기관 수집범위**에서는 EIA 신고기관과 ISO/RTO 공식 명부, 기관·고객별 근거, 아직 연결하지 못한 범위를 확인한다. 명부의 전수 추출은 모든 고객 신청과 진행 이력을 확보했다는 뜻이 아니다. PG&E·DTE·AES Ohio 같은 회사의 단계 점수를 권역 전체 점수로 확대하지 않는다.

**부하·피크 상세**와 **출처·갱신 상태**에서는 관측 간격, 잠정 피크, 수집 상태, 자료 기준일을 확인한다. 화면의 데이터 다시 읽기는 게시된 자료를 다시 조회하는 동작이며 원자료 수집·프로젝트 적재·평가 저장을 실행하지 않는다.

개별 원장의 **관측 시점**은 실제 저장된 앱 관측을 조회한다. 평가 기준일(`asOf`)과 근거가 알려진 시각(`knownAt`)을 구분하며, 앱의 첫 관측 이전은 자료 없음이다. 더 오래된 공식 원문은 **통합 시계열**에서 조회한다.

## 병목점수

**개별 프로젝트 평가**는 기술 검토, 계약·비용보증, 부지·인허가, 설비·계통 보강, 통전·운영 승인의 다섯 요건을 표의 열로 보여 준다. 각 요건은 `20 × (1 − 진행률)`의 잔여점수다. 다섯 요건 모두 확인된 미진행이면 100점, 모두 통과하면 0점이다. 미공개는 100점으로 채우지 않는다. 직접 평가에서 해당 없음으로 확인한 요건은 적용 요건의 합을 100점으로 환산한다.

표는 현재 검색 페이지의 행이다. 상단 평균과 유형·권역 요약은 선택한 유형·권역의 전체 적격 신청을 집계하므로 검색어·점수 상태·페이지 행 수와 분모가 다를 수 있다. 각 행의 원문 상태·모형 분류·날짜와 요건별 점수를 확인하고 사업명을 눌러 상세 근거를 읽는다.

요건별 공식 근거, 근거를 해석한 추정, 원장 단계에 적용한 **모형 가정**을 구별한다. 모형의 다섯 진행률은 실제 공정률이나 허가 취득의 직접 확인값이 아니다. 직접 근거가 일부라도 있으면 원장 단계 추정으로 비어 있는 요건을 채우지 않는다. [점수 산정과 집계 범위](SCORE_COVERAGE.md)를 참조한다.

**수용가** 유형을 선택하면 **수용가 권역별 평가**로 전환한다. 상단 권역 버튼, 권역 카드, 상세 권역 선택은 같은 선택값을 사용한다. 전체 권역 자료에서는 확보한 9개 권역의 출처와 점수 범위를 먼저 보고, 권역을 선택해 단계별 분포·평가 분모·과거 값을 확인한다. 개별 평가의 전체 유형 화면에서도 수용가 권역 카드를 바로 확인할 수 있다. `#scores/regional/PJM` 같은 주소로 선택한 권역을 공유하거나 다시 열 수 있다.

이 화면은 공개 개별 신청의 동일 가중 평균, 단계별 MW의 용량 가중 지수, 운영이 섞인 추적군 참고지수를 구분한다. 수용가 개별 원장과 다른 자료를 사용하므로 원장 검색·평가 상태·앱 관측일 필터를 적용하지 않는다. 해당 필터는 **개별 프로젝트 평가**에서 사용하며 수용가 공개 활성 원장 평균은 현재 NYISO 범위다. 서로 다른 분모를 하나의 전국 평균으로 합치지 않는다. [수용가 단계 모형과 분모](LOAD_BOTTLENECK.md)를 참조한다.

## 통합 시계열

### 지표 시계열

병목점수·신청 및 계약 용량·신청 및 사업 건수·실측 부하·일별 피크를 한 탐색 화면에서 고른다. 권역, 유형, 자료 종류, 출처·계열 검색어, 기간을 설정하고 **주 계열**과 **함께 볼 계열**을 선택한다. 같은 지표·단위의 두 계열을 비교할 수 있으며 점수는 동일한 가중 방식끼리 선택한다. 나란히 표시되는 계열도 모집단·정의·공개율이 같다는 뜻은 아니므로 각 계열의 범위를 함께 읽는다.

빠른 선택은 **전국 공개 원장**, **NYISO 전체 · 동일 7건**, **PJM 실제 부하**다. 차트 점, 시점 선택 메뉴 또는 **시점별 값과 근거** 표에서 기준일·공개일·보관본 포착일·취득시각과 분모를 확인한다. CSV는 현재 선택한 계열과 전체 선택 기간의 값을 내보내며 표의 현재 페이지만 내보내는 것은 아니다.

과거 점수는 **당시 원문 상태에 현재 모형을 적용한 재평가**다. 당시 발표된 점수나 당시 앱이 알고 있던 점수가 아니며, 성과를 검증한 예측 백테스트도 아니다. 신청자 구성 변화와 같은 사업의 진척은 다를 수 있어 NYISO 전체 집단과 고정 7건을 별도로 제공한다. 선은 공개 값 사이의 안내선이고 중간 시점의 상태를 보간하지 않는다. 누락과 집계 기준 변경은 차트 연결에서 구분한다.

실측 부하는 확보한 최근 관측 기간만 제공한다. 미래 부하 전망을 실측 역사에 섞거나 과거 관측 공백을 채우지 않는다. 일 피크는 시장 현지일 기준이며 일부 관측만 있으면 잠정값이다. 관측·취득 시각은 KST로 표시하고, 연·월·분기 자료는 원문의 날짜 정밀도를 유지한다. 축의 날짜 앵커가 실제 사업 진행일을 뜻하지 않는다.

### 프로젝트 생애주기

같은 신청 ID 또는 같은 고객·사업 위치를 확인한 다음 범위에서 개별 이력을 제공한다.

| 공개 이력 범위 | 동일 사업 판단과 한계 |
| --- | --- |
| NYISO 고정 7건 | 여러 보관본에서 같은 신청 ID로 확인되고 계속 활성·평가 가능했던 표본. 완료·철회 사업을 포함한 권역 전수 이력이 아님 |
| West · BPA 선별 원장 | 수용가 용도와 본토 주를 확인한 같은 `L` 신청 ID. 선별표에서 사라진 행의 이후 상태는 미확인 |
| MISO · DTE 2건 | Oracle Saline Township·Google Van Buren Township의 확인된 계약 근거. 건물 착공을 계통 보강 착공으로 바꾸지 않음 |

프로젝트와 시점을 선택해 원문 단계, 전체 점수, 다섯 요건의 가정 배점, 출처·날짜를 확인하고 **프로젝트 이력 CSV**로 내보낼 수 있다. MW로만 공개된 단계 집계, 연도 간 동일성이 확인되지 않은 익명 행, 여러 사업을 합친 행은 개별 생애주기로 만들지 않는다.

이 화면은 확보한 시점의 이력이며 모든 사업의 신청부터 통전·운영까지 전 생애주기를 확보한 것은 아니다. 원문에서 사라진 ID를 운영 완료 0점이나 미진행 100점으로 바꾸지 않는다. 집계 시점에 이전 개별 근거가 재사용된 경우 새 상태 확인이나 실제 단계 전환일로 표시하지 않는다.

### 앱 관측 기록

앱이 실제 저장한 원장·출처 관측의 범위를 확인한다. 공식 과거 원문을 읽어 만든 재평가와 앱에 과거부터 저장된 기록은 별개다. 새 관측 저장도 원자료의 신규 수집과 다르며 GitHub Pages에서는 읽기 전용이다.

## 공개 사이트와 정기 갱신

GitHub Pages는 공개 자료의 조회용 배포본이다. 7개 ISO/RTO 실측 부하는 GitHub Actions의 15분 목표 일정으로 수집·게시하며 실제 지연·실패·자료 시점은 화면에서 확인한다. 프로젝트 원장의 주간·월간 자동 적재와 평가 저장 API는 별도 운영 설정이 필요하다. 네 메뉴가 제공된다는 사실만으로 모든 출처의 자동 수집이나 쓰기 기능이 운영 중인 것은 아니다.

코드 검증, 저장소 반영, Pages 배포, 원자료 수집 성공을 별도로 확인한다. [Pages 운영](PAGES.md), [원장 수집·복구](OPERATIONS.md), [전체 데이터 범위](DATA.md)를 참조한다.
