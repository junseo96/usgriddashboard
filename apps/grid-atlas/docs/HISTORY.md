# 공식 자료로 복원한 과거 시계열

**관측 시계열 → 공식 과거 자료**에서 지표, 권역, 출처 계열, 시작·종료일을 선택한다. 그래프의 점 또는 아래 표를 선택하면 값, 평가 분모, 원자료 기준일, 발행일, 보관본 포착일·실제 관측일, 취득시각과 출처를 확인할 수 있다. 현재 선택한 계열은 CSV로 내려받는다. **앱 관측 기록**은 시스템에 실제 저장된 관측만 표시하는 별도 탭이다. 상단 프로젝트 기준일을 첫 앱 관측 이전으로 바꾸어도 공식 과거 자료는 조회할 수 있다.

## 확보한 범위

2026-10-09 검토본은 88개 계열에 543개 지표 값을 포함한다. 같은 원자료에서 점수·건수·용량과 권역별 값을 각각 산출하므로 543개의 독립적인 원장 또는 수집일을 뜻하지 않는다.

| 자료 | 과거 범위 | 제공 지표와 한계 |
| --- | --- | --- |
| LBNL 연간 발전·저장 활성 원장 | 2020–2025년 말, 6개 원장 | 본토 및 권역별 단계 추정 평균·활성 신청 수·유형별 MW. 전체 보기에서 하이브리드 신청은 한 번만 세고 발전·저장 MW를 합치지 않음 |
| NYISO 공식 원장의 보관본과 현재 취득본 | 2023-11-02, 2024-09-17, 2025-09-01, 2026-03-07, 2026-10-08 KST | 활성 수용가 점수·건수·MW. 앞의 네 날짜는 Internet Archive 포착일이며 원장의 기준일이 아님 |

공개 자료가 모든 권역·월·사업을 포괄하지 않는다. 데이터센터 신청 증가를 2022년부터 살펴볼 수 있지만, 미국 전체 데이터센터 신청의 시작 시점이나 완전한 전국 월별 총량을 확정한 것은 아니다. 회사별·ISO별 집계는 서로 중복될 수 있어 합산하지 않는다.

## 점수와 비교 방법

과거 원장에 **당시 기재된 상태**에 현재의 `stage-proxy-v1` 모형을 적용한다. 당시 이 점수를 발표했다는 의미도, 당시의 인허가·공사 진행률을 직접 확인했다는 의미도 아니다. 불명확한 상태는 미산출이며 평균에서 제외한다. 각 점에 적격 수·평가 수·미산출 수를 함께 제공한다. 배점은 [SCORE_COVERAGE.md](SCORE_COVERAGE.md)를 따른다.

LBNL의 2020년은 5,598개 중 2,149개, 2025년은 8,460개 중 6,655개에 점수를 부여할 수 있다. NYISO 활성 수용가 원장은 각 시점에 10 → 19 → 31 → 47 → 53건이며 마지막에는 52건을 평가할 수 있다. 매년 신규 접수·철회·완료와 수집 범위가 변하므로 평균 변화는 동일한 프로젝트 집단의 진척률이 아니다. 발전·저장 연말 값과 수용가 보관본 값을 같은 날짜의 전국 평균으로 합치지 않는다.

원자료가 없는 시점은 0이나 보간값으로 채우지 않는다. 그래프는 확보한 점만 표시하며 월·분기 자료의 공백과 명시된 비교 단절을 선으로 연결하지 않는다. 주요 단절은 다음과 같다.

- ERCOT 2024-07의 대상 연도 확대, 2025-08 앞의 자료 공백, 2025-11의 LLIS 전환, 2026-06의 중복·취소 항목 정리. 현재 추적 대상 466,497 MW와 개요의 다른 기준일·정의에 따른 요청 집계는 서로 대체하지 않는다.
- NYISO 과거 보관본은 Summer MW, 현재 수용가 시트는 Peak MW이므로 마지막 용량 구간을 연결하지 않는다. 이전 원장과 현재 시트의 범위 차이는 건수·점수 비교 시에도 확인해야 한다.
- PG&E 2026-03 기존 5,390 MW와 새 정의로 재작성된 5,090 MW를 별도 계열로 유지한다. 새 유료 검토 정의의 2026-06 값은 12,710 MW다.

## 날짜와 출처 보존

연·월·분기만 공개된 값은 그 정밀도를 유지한다. 그래프 정렬용 날짜는 해당 기간 첫날이며 실제 발표일이나 신청일로 간주하지 않는다. NYISO 보관본의 포착·관측 타임스탬프는 UTC 원문을 보존하고 화면 날짜는 KST로 표시한다. 원장 전체 기준일이 확인되지 않으면 `sourceAsOf`는 null이다. 뒤늦게 공개되거나 재작성된 값에는 실제 발행일을 표시하며 당시 알려진 값인 것처럼 저장하지 않는다.

각 점에는 실제 취득시각, 원문 URL, SHA-256을 보존한다. NYISO 보관본에는 공식 원본 URL도 별도로 남긴다. 출처 문서의 현재 URL에서 과거 바이트를 구할 수 없으면 해시가 다른 새 파일을 같은 과거 원장으로 사용하지 않는다.

## 재생성과 갱신

- `data/history-generation.json`: 연도별 LBNL 원문을 검증·정규화한 집계와 배제 내역.
- `data/history-nyiso.json`: 실제 보관본 및 현재 취득본의 수용가 상태·용량 집계.
- `data/history-load-reviewed.json`: 공식 문서에서 검토한 ERCOT·PG&E·PPL 지표와 출처.
- `data/history.json`: 위 자료를 공통 형식으로 결합한 읽기 전용 게시 데이터.

```sh
# 검토된 중간 자료로 게시 JSON을 재생성한다. 네트워크·DB 쓰기 없음.
node scripts/build-history.ts
node scripts/build-history.ts --check

# 원문 파서 및 출처 검증. 원문 없이 실행 가능한 일관성 검사.
python3 scripts/build-historical-generation.py --check
npm test
npm run test:python
```

원문부터 재생성하려면 각 Python 스크립트의 입력 규칙에 맞는 실제 XLSX와 취득 영수증을 별도로 준비한 뒤 `build-historical-generation.py --raw-dir /path/to/lbnl` 또는 `build-historical-nyiso.py --archive-dir /path/to/nyiso`를 실행한다. 원문·로컬 DB·자격증명은 커밋하지 않는다. 과거 원문 파서는 상태 범례·중복 식별자·지역·용량을 검증하며, NYISO 점수는 앱과 동일한 TypeScript 모형을 호출한다.

`/api/historical`과 `/api/historical/export`는 프로젝트 DB를 변경하지 않고 이 자료를 제공한다. Pages와 오프라인 HTML에도 포함한다. 재빌드는 과거 관측을 새로 만들거나 신규 자료를 수집하지 않는다. 새로운 공식 발표·보관본은 출처와 비교 가능성을 검토한 뒤 추가해야 한다. 이 기능이 프로젝트 원장의 주간·월간 자동 적재를 활성화하지는 않는다.
