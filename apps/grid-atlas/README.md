# Grid Atlas

미국 발전·저장·수용가의 계통접속 신청, 절차별 병목점수, 수집 공백과 시점별 이력을 다루는 독립 애플리케이션. 2026-10-08 새 구축 요청에 따라 작성했으며 기존 대시보드는 참고 자료로만 유지한다.

**[GitHub Pages 대시보드](https://junseo96.github.io/usgriddashboard/)**에서 공개 자료를 조회한다. 7개 ISO/RTO 실측 부하는 GitHub Actions의 15분 목표 일정으로 수집·게시한다. 전국 대형 수용가 시설·개발 목록은 별도 주간 Actions로 새 항목과 변경을 수집한다. 기존 접속 원장의 API 자동 적재와 평가 저장은 별도 운영 설정이 필요하다. 공개 자료에 없는 미국 전체 수용가 분모나 진행 근거를 임의로 만들지 않는다.

**수용가 기본 화면은 [전국 시설·개발 원장](docs/LARGE_LOAD_FACILITIES.md)**이다. 데이터센터와 대형 산업시설의 계획·공사·운영·중단, 개별 용량의 의미, 단계 근거와 보수적 추정 점수를 함께 확인한다. MW나 공식 큐 번호가 없다는 이유로 확인된 시설을 제외하지 않는다. 기존 신청·계약 원장은 보조 탭에 유지하며 두 모집단을 합산하지 않는다.

## 화면 구성

주 메뉴는 다섯 개다. [화면별 사용법과 비교 범위](docs/DASHBOARD.md)에서 필터·과거 재평가·분모를 확인한다.

| 메뉴 | 확인하는 내용 |
| --- | --- |
| 전국 개요 | 공개 신청의 평균·평가 범위, 발전·저장 장기 변화 또는 전체 평균의 실제 관측, 7개 ISO/RTO 부하·피크와 접속 신청 비교 |
| 권역별 프로젝트 | 개별 프로젝트, 수용가 파이프라인, 부하·피크 상세, 사업자·기관 수집범위, 출처·갱신 상태 |
| 병목점수 | 개별 프로젝트의 다섯 요건별 잔여점수, 수용가 권역별 평가, 산정 기준 |
| 통합 시계열 | 용량 가중 점수·건수·용량 시계열, 확인된 개별 프로젝트 생애주기, 실제 앱 관측 기록 |
| 송배전 제약 | 송전 제약·시장 관측과 배전 접속 여유·보조 신뢰도 자료를 구분해 확인 |

2026-10-13부터 평균 집계는 [용량 가중 방식](docs/CAPACITY_WEIGHTING.md)을 사용한다. 개별 절차 점수와 원자료 관측을 보존하고, 과거 평균도 해당 시점의 공개 MW로 재계산한다. 공개되지 않은 용량·단계·과거 시점을 만들지 않는다.

## 실행

이 디렉터리(`apps/grid-atlas`)에서 Node.js 24 및 Python 3.12로 실행한다.

```sh
npm ci
npm run dev
```

서버 실행 전 초기 자료와 SQL migration을 준비한다. 재실행은 기존 평가와 관측을 보존한다. 로컬 데이터는 `.state/grid-atlas.sqlite`, 개발 화면은 포트 5175, API는 8789를 사용한다. 원격 클라우드의 이 포트가 사용자에게 공개된 주소라는 뜻은 아니다.

```sh
npm run typecheck
npm test
npm run test:python
npm run build
```

배포 없이 화면을 열어보려면 실행 중인 로컬 API와 빌드를 이용해 오프라인 HTML을 만든다. 이 파일은 실제 관측을 고정한 읽기 전용이며 변경사항을 저장하지 않는다.

```sh
node scripts/export-preview.mjs --output .state/grid-atlas-preview.html
```

## 구조

- `src/`: React 대시보드, 프로젝트 상세·근거 입력, 출처·시계열·산식 설명.
- `shared/`: 버전이 있는 공통 데이터 규격과 순수 점수 함수.
- `server/`: 같은 API를 사용하는 Cloudflare D1 / 로컬 SQLite 어댑터. 운영 쓰기는 서버 비밀값 인증 필요.
- `migrations/`: 스키마 변경. 적용한 migration은 수정하지 않고 새 파일을 추가.
- `scripts/`: 초기 적재, 검증된 공식 원문 수집, 배포 설정, 미리보기 내보내기.
- `data/`: 출처와 날짜가 보존된 초기 정규화 원장. 합성 평가 없음.
- `data/grid-demand.json`: 실제 ISO/RTO 관측과 시장 현지일 피크. `public/data/load-pipeline.json`: 신청·계약·공시·참고 자료 및 범위별 집계.
- `data/history.json`: 검증한 과거 공식 원장의 점수·건수·용량 및 수용가 공시 계열. 앱 DB 관측과 별도로 Pages에도 포함한다.
- `data/load-bottleneck.json`: 권역별 수용가 단계 분포와 과거 점수. 프로젝트 수·MW 가중치와 추적군 참고지수를 구분한다.
- `data/load-coverage.json`: 전국 EIA 신고기관 명부, ISO/RTO 공식 명부, 기관·고객별 근거와 아직 연결하지 못한 수집 범위.
- `tests/`: 실제 SQL·모델·원문 파서 검증.
- 저장소의 `.github/workflows/grid-atlas-*.yml`: 검사, 수동 배포, 명시적으로 활성화하는 주간/월간 수집.

## 점수의 의미

5개 독립 요건의 잔여점수는 각각 `20 × (1 − 진행률)`. 확인된 미진행 5개는 100점, 모두 통과하면 0점. 공식 수치와 근거가 있는 정성 추정을 구분하며, 미공개는 점수를 부여하지 않고 별도 집계한다. 점수는 지연 기간이나 완공 확률이 아니다.

전국 개요에는 직접 근거로 산출한 점수 또는 공개 원장 단계에 따른 추정 점수가 있는 적격 신청의 용량 가중 평균을 제공한다. 분모 GW와 평가 건수, 점수·용량 누락을 함께 표시하고 프로젝트 수 평균은 보조값으로 둔다. 단계 추정은 `stage-proxy-v1`의 다섯 요건별 가정을 사용하며, 저장된 직접 근거 평가와 별도로 표시한다. 단계 자체가 불명확한 신청은 미산출이다. 요건별 근거가 일부라도 저장된 신청은 원장 단계 모형으로 덮어쓰지 않는다. [단계별 배점과 범위](docs/SCORE_COVERAGE.md)를 참조한다.

미국 전체 물리 프로젝트의 전수 평균이라고 부르지 않는다. 유형별 평균은 해당 유형 MW를, 전체 평균은 공개된 설비·부하 MW 성분 합을 사용한다. 동일 원장 ID의 발전·저장 하이브리드는 전체에서 한 번만 세며, 전체 용량 합은 공용 접속점 한도나 순수요를 뜻하지 않는다.

**권역별 프로젝트 → 사업자·기관 수집범위**에서 EIA 2025년 전체 신고기관 3,421개, ISO/RTO 공식 구역·역할 명부, 권역 취합기관과 회사별 근거를 먼저 확인한다. PG&E·DTE·AES Ohio만으로 각 권역을 대표하지 않으며 CEC, MISO, PJM의 더 넓은 자료와 남은 공백을 함께 보여 준다. 명부 기관 수는 고객 신청 수가 아니고, 기관별 자료 연결은 프로젝트 전수 확보율이 아니다. [명부·출처·수집 공백](docs/LOAD_COVERAGE.md)을 참조한다.

**병목점수 → 수용가**는 시설·개발 원장이 기본이다. 별도 **수용가 권역별 평가**에서 7개 ISO/RTO와 West·Southeast의 공개된 일부 범위를 바로 확인한다. 상단 권역 선택과 상세 자료가 연동되며 선택한 권역 주소로 다시 열 수 있다. 평균은 해당 시점의 확인된 MW로 가중하며, 건수만 공개된 자료는 건수 보조값과 용량 평균 미산출을 구분한다. 출처·모집단이 다른 집계는 합산하지 않는다. NYISO 전체 원장과 동일 7건의 진척을 비교할 수 있고, 운영이 섞인 집단은 참고지수로 구분한다. [권역별 분모·배점·과거 비교의 한계](docs/LOAD_BOTTLENECK.md)를 참조한다.

원장 관측, 상태 적용일, 근거를 확인한 시각, 시스템에 저장된 시각을 구분한다. `asOf`는 상태 기준일, `knownAt`은 그때까지 시스템이 알고 있던 근거의 범위다. 앱의 첫 관측 이전은 자료 없음이며 당시 원장이 없는 기간을 현재 자료로 채우지 않는다. **통합 시계열 → 지표 시계열**에서는 실제 과거 원장·공시, 권역 수용가 단계 자료, 확보한 부하·피크를 필터로 탐색한다. 과거 점수는 당시 상태에 현재 모형을 적용한 재평가이며 당시 발표된 점수가 아니다. **프로젝트 생애주기**는 같은 신청 ID나 사업 위치를 확인한 NYISO 고정 7건·BPA 선별 원장·DTE 2건의 공개 시점만 연결한다. 모든 프로젝트의 신청부터 운영까지 전 이력을 확보한 것은 아니며 앱 관측을 소급 생성하지 않는다.

조회·평가의 날짜 단위는 KST(UTC+09:00)다. `asOf`는 해당 KST 날짜의 23:59:59.999까지 조회하며, 날짜만 있는 적용일·발행일·수집 확인일은 KST 달력 날짜로 비교한다. 정확한 확인·기록 시각과 `knownAt`은 UTC 타임스탬프로 보존한다. 원자료의 날짜 문자열과 공개 정밀도는 바꾸지 않으며, 날짜 경계 계산을 실제 사건 발생 시각으로 저장하지 않는다.
