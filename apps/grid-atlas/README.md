# Grid Atlas

미국 발전·저장·수용가의 계통접속 신청, 절차별 병목점수, 수집 공백과 시점별 이력을 다루는 독립 애플리케이션. 2026-10-08 새 구축 요청에 따라 작성했으며 기존 대시보드는 참고 자료로만 유지한다.

**[GitHub Pages 대시보드](https://junseo96.github.io/usgriddashboard/)**에서 공개 자료를 조회한다. 7개 ISO/RTO 실측 부하는 GitHub Actions의 15분 목표 일정으로 수집·게시한다. 프로젝트 원장 주간·월간 자동 적재와 평가 저장 API는 별도 운영 설정이 필요하다. 공개 자료에 없는 미국 전체 수용가 분모나 진행 근거를 임의로 만들지 않는다.

## 실행

이 디렉터리(`apps/grid-atlas`)에서 Node.js 24 및 Python 3.12로 실행한다.

```sh
npm ci
npm run dev
```

서버 실행 전 초기 자료와 SQL migration을 준비한다. 재실행은 기존 평가와 관측을 보존한다. 로컬 데이터는 `.state/grid-atlas.sqlite`, 개발 화면은 포트 5175, API는 8789를 사용한다. 원격 클라우드의 이 포트가 사용자에게 공개된 주소라는 뜻은 아니다.

```sh
npm run typecheck
npm test
npm run test:python
npm run build
```

배포 없이 화면을 열어보려면 실행 중인 로컬 API와 빌드를 이용해 오프라인 HTML을 만든다. 이 파일은 실제 관측을 고정한 읽기 전용이며 변경사항을 저장하지 않는다.

```sh
node scripts/export-preview.mjs --output .state/grid-atlas-preview.html
```

## 구조

- `src/`: React 대시보드, 프로젝트 상세·근거 입력, 출처·시계열·산식 설명.
- `shared/`: 버전이 있는 공통 데이터 규격과 순수 점수 함수.
- `server/`: 같은 API를 사용하는 Cloudflare D1 / 로컬 SQLite 어댑터. 운영 쓰기는 서버 비밀값 인증 필요.
- `migrations/`: 스키마 변경. 적용한 migration은 수정하지 않고 새 파일을 추가.
- `scripts/`: 초기 적재, 검증된 공식 원문 수집, 배포 설정, 미리보기 내보내기.
- `data/`: 출처와 날짜가 보존된 초기 정규화 원장. 합성 평가 없음.
- `data/grid-demand.json`: 실제 ISO/RTO 관측과 시장 현지일 피크. `public/data/load-pipeline.json`: 신청·계약·공시·참고 자료 및 범위별 집계.
- `tests/`: 실제 SQL·모델·원문 파서 검증.
- 저장소의 `.github/workflows/grid-atlas-*.yml`: 검사, 수동 배포, 명시적으로 활성화하는 주간/월간 수집.

## 점수의 의미

5개 독립 요건의 잔여점수는 각각 `20 × (1 − 진행률)`. 확인된 미진행 5개는 100점, 모두 통과하면 0점. 공식 수치와 근거가 있는 정성 추정을 구분하며, 미공개는 점수를 부여하지 않고 별도 집계한다. 점수는 지연 기간이나 완공 확률이 아니다.

전국 개요에는 직접 근거로 산출한 점수 또는 공개 원장 단계에 따른 추정 점수가 있는 적격 신청의 동일 가중 평균을 제공한다. 단계 추정은 `stage-proxy-v1`의 다섯 요건별 가정을 사용하며, 저장된 직접 근거 평가와 별도로 표시한다. 단계 자체가 불명확한 신청은 미산출이다. 요건별 근거가 일부라도 저장된 신청은 원장 단계 모형으로 덮어쓰지 않는다. [단계별 배점과 범위](docs/SCORE_COVERAGE.md)를 참조한다.

용량 가중 평균이 아니며, 미국 전체 물리 프로젝트의 전수 평균이라고 부르지 않는다. 동일 원장 ID의 발전·저장 하이브리드는 전체 집계에서 한 번만 세고 유형별 보기에는 중복될 수 있다.

원장 관측, 상태 적용일, 근거를 확인한 시각, 시스템에 저장된 시각을 구분한다. `asOf`는 상태 기준일, `knownAt`은 그때까지 시스템이 알고 있던 근거의 범위다. 첫 관측 이전은 자료 없음이며 당시 원장이 없는 기간을 현재 자료로 채우지 않는다.

조회·평가의 날짜 단위는 KST(UTC+09:00)다. `asOf`는 해당 KST 날짜의 23:59:59.999까지 조회하며, 날짜만 있는 적용일·발행일·수집 확인일은 KST 달력 날짜로 비교한다. 정확한 확인·기록 시각과 `knownAt`은 UTC 타임스탬프로 보존한다. 원자료의 날짜 문자열과 공개 정밀도는 바꾸지 않으며, 날짜 경계 계산을 실제 사건 발생 시각으로 저장하지 않는다.
